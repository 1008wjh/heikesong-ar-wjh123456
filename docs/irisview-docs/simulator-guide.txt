01 / 操作指南
Client 与 Simulator
本版模拟器在窗口标题中显示 LLVISION Agent Platform - Mono 或 LLVISION Agent Platform - Stereo，分别对应单目和双目显示。
Client 用于管理和操作应用，Simulator 显示应用输出。运行示例后，通常会同时出现这两个窗口。

IrisView Client · 操作入口
查看连接、选择应用、启动或结束应用。本指南中的提词卡使用详情页的文字输入框。

IrisView Simulator · 显示窗口
独立显示应用输出。本指南中的示例使用黑底绿色画面。

呼吸示例自动播放。要试用文字输入，可另行准备提词卡安装包。

02 / 操作指南
准备运行环境
准备 Kit 和呼吸示例包，然后检查文件路径与运行环境。

Windows 电脑
使用 x86_64 电脑上的 WSL2 + Ubuntu 22.04 / 26.04，并具备 WSLg 图形窗口支持。从开始菜单打开 Ubuntu，再执行本指南命令。

Ubuntu 电脑
使用 x86_64 的 Ubuntu 22.04 / 26.04，在已登录的图形桌面中打开终端。本版 Kit 未提供原生 Windows、macOS 或 ARM64 运行环境。

命令都在 Ubuntu 终端中执行。在 Ubuntu 的 Bash 终端中执行命令，将 Kit 和项目保存在 Linux 文件系统。

所需文件与工具
LLVISION Developer Kit v1.0.0。按照工具包解压说明准备目录。
呼吸示例。解压 IrisView-Platform-Alpha-中英双语版-v3.zip，在 Breathe/ 目录中找到源码和 breathing.fuiapp。
如果要从源码构建：在 Ubuntu 内配置 Node.js 24.13.0 / npm 11.6.2 和 Git。仅启动 Kit 的 Client 无需另装 Node；修改和构建源码时才需要上述工具链。

首次准备：把文件放到哪里按照主机环境说明配置 Ubuntu 或 WSLg。把 KIT 设为工具包中包含 bin/ 和 SHA256SUMS 的目录。
在 Ubuntu 中，Windows 的 C 盘位于 /mnt/c。例如，下载的文件位于 /mnt/c/Users/用户名/Downloads/。按提示粘贴完整路径，并保留文件名中的空格。
.fuiapp 是可运行的应用安装包。下面将呼吸示例包复制到 DEMO 目录，并统一文件名。终端询问路径时，粘贴文件的完整 Linux 路径，不要额外加引号。已有同名文件时，cp -i 会询问是否覆盖。
复制DEMO="$HOME/IrisView-Developer-Kit-Data"
mkdir -p "$DEMO"
read -r -p "呼吸示例 .fuiapp 的完整路径：" BREATHE_PACKAGE
cp -i -- "$BREATHE_PACKAGE" "$DEMO/breathing.fuiapp"
直接运行 breathing.fuiapp 即可体验示例。要修改呼吸节奏，请打开同一目录中的 src/rhythm.js。
下面采用统一目录。请把 Kit 和呼吸安装包放到相应位置；若你的路径不同，修改变量右侧即可。~ 代表当前 Ubuntu 用户的主目录。
复制KIT="$HOME/IrisView/LLVISION/IrisView-Developer-Kit-v1.0.0"
DEMO="$HOME/IrisView-Developer-Kit-Data"
cd "$KIT"
ls "$DEMO/breathing.fuiapp"
检查环境
依次执行两步运行环境检查，全部通过后再运行示例。若某项失败，先处理该项错误。新开终端时需重新设置 KIT 和 DEMO。
--runtime-only 只检查运行环境，适用于体验已有安装包。需要修改源码时，再安装 Node.js 24.13.0、npm 11.6.2 和 Git，并运行不带该参数的 doctor。完整系统准备见主机环境说明。
复制"$KIT/bin/check-host"
"$KIT/bin/irisview" doctor --runtime-only
✓ 应该看到检查结果通过；doctor 报告 status: pass。如果提示缺少依赖，按下方说明处理。
安装缺失的系统依赖在 Kit 根目录运行 ./bin/install-host-dependencies，阅读它列出的安装计划，按提示输入 INSTALL 后安装；然后重新运行检查。该工具不会安装 Node，也不会替你配置图形桌面。不要用 sudo 运行整个 Kit。没有 Ubuntu / WSLg 的电脑，请先按主机环境说明完成系统准备。

04 / 操作指南
应用管理
在 Client 中查看连接状态、选择应用并管理运行状态。

连接区 · 左上
模拟器连接显示“模拟连接”。模拟器不提供真实眼镜的电量，显示未知属于正常情况。

应用区 · 左下
点击应用名称查看详情。应用旁的“启动”可启动它；切换详情不等于切换运行中的应用。

详情区 · 右侧
查看运行状态，使用“启动”“休眠”“结束应用”等控制；提词卡的文字输入框也位于此处。

＋ 点击放大图 3 · “未启动”状态下，点击右上角“启动”左侧已安装应用仍然保留。点击右上角蓝色“启动”，再观察状态是否变为“前台运行”。“关屏 / 点亮”控制显示状态，“结束应用”控制应用生命周期。第一次体验时保持屏幕点亮，使用应用启动与结束按钮即可。

05 / 操作指南
发送文字
在 Client 中发送短稿，使用指令翻页或自动播放。

01可选输入练习：另备提词卡安装包，复制到 $DEMO/prompt-cards.fuiapp 后再执行
关闭 Client 后，等待原终端重新出现提示符，再执行下列命令。
复制"$KIT/bin/irisview" verify "$DEMO/prompt-cards.fuiapp" --allow-debug-unsigned
"$KIT/bin/irisview" run "$DEMO/prompt-cards.fuiapp" --allow-debug-unsigned --display-mode mono
02找到输入框，填入一段短稿
选中前台运行的“随身提词卡”。在详情页输入以下文字，用英文竖线 | 分页，再点击右侧蓝色“发送”。
复制欢迎体验IrisView|把提示放在眼前|接下来演示交互
＋ 点击放大图 4 · 短稿填在应用详情页的输入框中输入框位于“AI 助手”标签下，右边是“发送”。截图展示发送前的文字。提词卡的控制入口本示例复用了 Client 的预设输入框，因此仍显示“AI 助手”等标签。提词卡仅接收输入框提交的文字；控制播放请发送下表中的斜杠指令，勿使用“询问天气 / 重播 / 重置”按钮。

03切到模拟器，检查第一页
＋ 点击放大图 5 · 短稿发送后的显示结果✓ 应该看到画面显示第一段文字与“1/3 · 暂停”。发送播放指令后才会自动翻页。
04用同一个输入框控制翻页
发送成功后输入框会自动清空。在同一输入框输入 /下一页 并点击“发送”，确认页码变为 2/3、正文为“把提示放在眼前”。再输入 /继续 并发送；约 6 秒后显示第三页，再停留约 6 秒后停止。每次只发送一条指令。

发送内容 | 会发生什么 | 
/下一页 | 切换到下一页，并暂停自动播放。 | 
/上一页 | 返回上一页，并暂停自动播放。 | 
/继续 | 每 6 秒自动翻页；末页停留 6 秒后结束。已在末页时发送，会从第一页重播。 | 
/暂停 | 停在当前页。 | 
/重置 | 恢复默认示例卡，回到第一页并暂停。 | 

提词卡接收的整段文字最多为 192 UTF-8 字节，纯中文通常约 64 字；标点和分隔符也计入。每行按 12 个 Unicode 码点换行，每页最多 3 行，多出的内容另起一页。短稿只保存在本次运行中，重启应用后恢复默认内容。此限制属于该示例使用的输入通道。

06 / 操作指南
切换显示模式
启动参数 --display-mode 选择单目或双目显示，两种模式使用同一个安装包。

mono · 单目
显示左眼画面，输出为 640 × 480。窗口较紧凑，适合查看文字和界面布局。

stereo · 双目
左右眼并排显示，总输出为 1280 × 480。适合检查左右眼呈现；立体效果取决于应用为左右眼提供的内容。

关闭当前 Client，等待终端返回，再将启动命令末尾改为 --display-mode stereo。
复制"$KIT/bin/irisview" run "$DEMO/breathing.fuiapp" --allow-debug-unsigned --display-mode stereo
＋ 点击放大图 6 · Stereo 模式下左右眼并排显示这是重新启动后的默认示例卡。两侧均显示提词内容；可以检查换行、内容完整性和左右眼是否符合预期。窗口标题应包含 Stereo，显示区域明显变宽。恢复单目时，关闭会话并用 mono 重新启动。显示模式决定单目或双目画面；诊断配置（profile）决定记录哪些诊断信息，两者独立。
上面的命令用呼吸应用比较两种显示模式。图中提词卡仅用于展示双眼窗口的排列方式。

07 / 操作指南
结束应用与退出会话
“结束应用”停止当前应用；关闭 Client 则结束整个运行会话。

在 Client 右上角点击“结束应用”。出现确认框后，确认要停止的是当前应用。
在确认框再次点击“结束应用”。详情页变为“未启动”，之后仍可点击“启动”再次运行。
退出会话时，关闭 Client 窗口。也可以回到运行命令的终端按 Ctrl+C，结束本次会话及模拟器。
＋ 点击放大图 7 · 结束应用前的确认框“结束应用”停止当前应用，不会卸载它，也不会直接退出整个 Client 会话。
08 / 操作指南
常见问题
根据现象检查路径、环境、应用状态或日志。提交问题时保留启动命令、复现步骤和错误信息。

看到的现象 | 先做这一步 | 

路径不存在 / 找不到文件 | 确认已设置 KIT、DEMO，目录拼写与解压后的实际目录一致。运行 ls 检查两个 .fuiapp 是否存在。 | 

没有图形窗口 | 检查是否在 Ubuntu 图形桌面或支持 WSLg 的 WSL2 中运行；依照主机环境说明检查显示环境。 | 

只有空白 Client | 确认 run 后面带了 .fuiapp 路径。已安装应用显示“未启动”时，选中它并点击“启动”。 | 

提示端口被占用 | 先关闭已有 Client，等待其终端返回，再启动下一次。默认会话端口为 28045。 | 

包校验或信任检查失败 | 先执行 verify 查看原因。开发未签名包需要对应调试参数；正式包检查签名和发布者信任配置。 | 

预览关闭，但应用前台运行 | 切换到独立 Simulator 窗口查看输出。Client 的宣传图不会随应用内容实时更新。 | 

发送后没有自动翻页 | 提词卡默认暂停。确认前台运行，发送 /继续；手动翻页也会暂停。检查输入未超过 192 字节。 | 

黑屏、图像异常或 system-error | 先确认屏幕已点亮、应用处于前台。若仍异常，保存应用包版本、显示模式和日志。历史测试出现过间歇性资源解码错误与 system-error，原因尚未确认。 | 

修改后安装提示版本冲突 | 修改包内容后递增 manifest 的 versionCode，再构建打包。不要直接清空共享状态目录绕过版本检查。 | 

check-host 或 doctor 报告依赖缺失 | 根据检查输出安装缺少的系统依赖。体验已有安装包时运行 doctor --runtime-only，从源码开发时运行 doctor。补齐依赖后重新执行检查。 | 
提示 Permission denied | 确认使用 Linux tar 解压原始 Kit，并将 KIT 指向含 bin/ 的根目录。不要用 sudo 启动整个 Kit，也不要对所有文件批量 chmod 来掩盖解压问题。 | 

日志位置与诊断模式默认运行配置为 release。以下命令查询该配置的状态目录与状态；在返回目录的 logs 中查找日志。
复制"$KIT/bin/irisview" state path --profile release
"$KIT/bin/irisview" state status --profile release
需要更多诊断信息时，先关闭 Client，再启动 analysis 模式。未显式指定 profile 时，它默认使用 diagnostic。
复制"$KIT/bin/irisview" run "$DEMO/breathing.fuiapp" --allow-debug-unsigned --client-mode analysis --display-mode mono
反馈问题时附上：SDK 版本、Ubuntu 版本、应用包版本、启动命令、实际画面、复现步骤和相关错误日志。如果启动时指定过自定义 --state-dir，直接到那个目录的 logs 中查找本次日志。
