调试同一应用时，可在 run 命令中同时指定 --allow-debug-unsigned 和 --allow-debug-replace，显式替换已安装的同版本未签名调试包。正常升级仍需递增 versionCode。
构建 Linux 和 Android 应用包，使用受信任的发布者密钥签名，然后安装到目标 Client。
构建路径
test→build→package→verify→运行检查
构建器为 Linux 与 Android 准备相同源码。如果项目使用 TypeScript 或需要生成图片等资源，应在构建前完成转译和资源生成。
Kit 打包已准备好的源码和资源。项目使用 npm 依赖时，先在项目中完成安装和构建，再把生成的文件交给 Kit。
版本规则
应用更新保持 ID 与发布者身份不变，包内容变化时递增 versionCode。相同安装包可重复安装；常规安装会拒绝相同版本码的不同内容、降级或签名身份变化。
调试与正式交付
--debug-unsigned 与 --allow-debug-unsigned 仅用于明确启用的本地开发流程。普通 Client 要求受信任发布者签名。验签成功、analysis 模式或 --trusted-key 都不会自动注册新发布者。
发布者签名使用提供方批准的流程与密钥 ID；私钥保留在受保护的签名环境，不放进 Kit、源码或文档。普通开发者提交源码或包，由授权流程完成签名。
迁移旧应用的文字对齐
旧应用中使用的 TextAlign.LEFT 和 TextAlign.RIGHT 已移除。将它们分别改为 TextAlign.TOP_LEFT 和 TextAlign.TOP_RIGHT，可保留原有的左上角和右上角对齐效果。重新打包后，在新模拟器中打开包含这些文字的界面；test 和 verify 都可能通过，仍需运行应用验证。
