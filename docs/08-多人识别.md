# 多人识别（说话人分离 / diarization）

> v3 目标：从「说一句话认一个人」升级为「一场会里谁在什么时候说话」。
> 本版先做**离线、CPU、可断网**的多人分离 + 实名映射；云端 ASR / LLM 纪要只预留接口。

## 1. 现在仓库里有什么（v2 基线）

| 环节 | 现状 |
|---|---|
| 采集 | 眼镜按一下「确认」录 4 秒，`POST /api/voice/scan` 送一段 16k 单声道 wav |
| 声纹 | `src/voice.py`：CAM++（3D-Speaker 中文通用）192 维，余弦 + 阈值 0.72 + 领先第二名 0.08 |
| 识人 | `1:N`：拿这段音频和 `data/people.json` 里所有人的 `voice_embeddings` 比 |
| 展示 | `POST /api/latest` 轮询，把结果压成卡片给眼镜 |
| 人脸 | `src/face.py`：YuNet + ArcFace，第二条通道，同一套卡片 |

v2 的隐含假设是**一次只有一个人在说**，且只回答「这是谁」。v3 要回答的是
「**这段会议音频里有几个人、谁在什么时候说、其中哪些是我们认识的人**」。

## 2. v3 链路

```
眼镜/手机分片上传（16k mono wav）
        │  POST /api/v1/audio/upload
        ▼
MeetingStore（data/meetings/<sid>/chunk_XXXX.wav + meta.json）
        │  POST /api/v1/session/<sid>/finalize
        ▼
src/diarize.py
  ├─ ① 分段：pyannote segmentation-3.0（ONNX，5.72MB）
  ├─ ② 重叠清洗：默认丢弃重叠段（轮流说话场景，重叠=垃圾）
  ├─ ③ 声纹：逐段走 CAM++（复用 src/voice.py，27MB）
  ├─ ④ 聚类：贪心最近质心 + 质心二次合并（余弦 ≥ AR_DIAR_MERGE_SIM）
  └─ ⑤ 实名：簇质心与人脉库比对（复用 0.72 / 0.08），一人最多认领一簇
        │
        ▼
meta.json（speakers / segments / asr / summary）
  ├─ GET  /api/v1/session/<sid>/transcript   转写分段（带实名）
  ├─ POST /api/v1/speaker/bind               匿名 spk → 实名（可顺带录入声纹）
  ├─ GET  /api/v1/audio/play?timestamp=…      时间锚点回放
  ├─ POST /api/v1/action/trigger              summary / ask / mark（预留）
  └─ /api/latest                            眼镜卡片：会议 · N 人 · 每人时长
```

设计取舍：

- **不用 sherpa-onnx 自带聚类**。实测 3 人测试集上它把 B/C 合成一个 speaker（`num_clusters=3` 也只出 2 簇），
  且不好把匿名 spk 绑回人脉库；所以只借它的 pyannote 分段，聚类自己做（见 `tools/diarize_sweep*.py` 的对比）。
- **分段/聚类/映射三段可独立替换**：将来上云或换模型，只改 `diarize.py`，会话与 API 不变。
- **离线优先**：没有 key、断网也能演示；云端 ASR 通过 `src/asr.py` 适配器按需打开。

## 3. 模型选型（国际 / 国内）

### 3.1 国际

| 模型/工具 | 类型 | 许可 | 中文 | 体积/算力 | 适合场景 |
|---|---|---|---|---|---|
| **pyannote.audio 3.x / segmentation-3.0** | 分段+聚类全流程 | MIT（代码）；模型需在 HF 同意条款 | 好 | PyTorch，CPU 可跑但慢 | 追求 DER 精度、可上 GPU |
| **NVIDIA NeMo Sortformer（diar_sortformer_4spk-v1）** | 流式 diarization | Apache-2.0 | 好 | 建议 GPU | 实时会议、≤4 人、要低延迟 |
| **NeMo TitaNet** | 说话人 embedding | Apache-2.0 | 好 | 小 | 需要高质量 embedding |
| **WeSpeaker（ResNet34 / ECAPA）** | embedding | Apache-2.0 | 中 | 小 | 自建声纹库 |
| **SpeechBrain ECAPA-TDNN** | embedding | Apache-2.0 | 中 | 小 | 教学/快速验证 |
| **Silero VAD** | 端点检测 | MIT | 语言无关 | 2MB | 前置 VAD，别把静音送进模型 |
| **WhisperX** | ASR + diarization 管线 | BSD-2 | 好 | GPU 友好 | 要"文字+说话人+时间戳"一条龙 |

### 3.2 国内

| 模型/平台 | 类型 | 许可/计费 | 中文 | 体积/算力 | 适合场景 |
|---|---|---|---|---|---|
| **阿里 3D-Speaker（CAM++ / ERes2NetV2）** | embedding + diarization 工具箱 | Apache-2.0 | **强（20 万中文说话人）** | CAM++ ONNX 27MB，CPU 1s 音频≈20ms | 本仓库当前选型 |
| **FunASR（Paraformer / SenseVoiceSmall + FSMN-VAD + CAM++）** | ASR + 匿名说话人管线 | MIT | 强 | PyTorch，CPU 可用 | 要离线转写 + spk 分段 |
| **阿里云智能语音交互 / 通义听悟** | 云端 ASR + 说话人分离 | 按量计费，有免费额度 | 强 | 无需本地算力 | 正式会议纪要、长音频 |
| **腾讯云 ASR** | 云端 ASR + 说话人分离 | 按量计费 | 强 | 无需本地算力 | 备选，短音频 ≤60s/3MB，长音频走异步 |
| **火山引擎录音文件识别** | 云端 ASR + 说话人分离 | 按量计费 | 强 | 无需本地算力 | 备选，长音频异步 |
| **讯飞 / 百度智能云** | 云端 ASR | 按量计费 | 强 | 无需本地算力 | 备选 |

### 3.3 本仓库为什么选"pyannote 分段 + CAM++ 聚类"

| 维度 | 结论 |
|---|---|
| 离线 | ✅ 两个 ONNX 都本地跑，断网可用 |
| 体积 | ✅ 5.72MB + 27MB（CAM++ 仓库原有） |
| 算力 | ✅ CPU：35.8s 三人会议整场 finalize ≈ 4.5s |
| 中文 | ✅ CAM++ 是 20 万中文说话人训练的，中文效果优先 |
| 依赖 | ✅ 只多一个 `sherpa-onnx`（仓库 v2 已依赖） |
| 可替换 | ✅ 云端/NeMo/FunASR 都在 `asr.py` / `diarize.py` 留了位置 |

**什么时候换：**

- 要**离线转写** → 上 FunASR（SenseVoiceSmall + FSMN-VAD + CAM++），代价是 PyTorch 依赖和 ~1GB 模型。
- 要**实时流式**（边说边出 spk） → NeMo Sortformer（≤4 人、建议 GPU），或本仓库后续的增量聚类。
- 要**最高 DER / 长会议** → pyannote.audio 3.1（GPU + HF token）。
- 要**中文长音频 + 纪要 + 知识库** → 阿里云/腾讯云/火山 云端 ASR，`src/asr.py` 已留 `aliyun / tencent / volcano` 三个适配器。

## 5. API 契约（v1，已实现本地版）

> 统一返回 `{"ok": true, ...}`；失败返回 500 + `{"ok": false, "error": "..."}`（沿用仓库现有风格）。
> 路径与本地《AR眼镜声纹智能助手 开发者文档》的 `/api/v1/*` 对齐，方便以后换 SpringBoot 中台。
> `audio`/`image` 的"本地绝对路径"只对**本机请求**生效（远端必须 base64/dataURL）；安全细节见 [09-安全审计](09-安全审计.md)。

| 方法 | 路径 | 入参 | 出参 |
|---|---|---|---|
| POST | `/api/v1/session/create` | `{title?, userId?}` | `{sessionId, status:"collecting", ...}` |
| POST | `/api/v1/audio/upload` | `{sessionId, seq?, audio}`（base64 / dataURL / 本地路径，wav/pcm） | `{received, seconds, duration, chunks}` |
| POST | `/api/v1/session/{id}/finalize` | `{asr?: bool}` | `{duration, speaker_count, speakers[], segments[], asr:{...}}` |
| GET | `/api/v1/session/{id}` | — | 会议 meta（不含质心） |
| GET | `/api/v1/session/{id}/transcript` | — | `{speakers[], segments[{start,end,spk_id,speaker,text}]}` |
| GET | `/api/v1/session/{id}/card` | — | 眼镜卡片（2–4 行） |
| GET | `/api/v1/sessions` | — | 会议列表（按更新时间倒序） |
| POST | `/api/v1/speaker/bind` | `{sessionId, spkId, personId\|name, enroll?:bool}` | 更新后的 meta；`enroll=true` 把簇质心写进该人声纹 |
| DELETE | `/api/v1/session/{id}` | — | 删除整场会议（音频/质心/转写） |
| GET | `/api/v1/audio/play` | `?sessionId&timestamp&before=3&after=3` | `audio/wav` 片段（锚点回放） |
| POST | `/api/v1/action/trigger` | `{sessionId, actionType: summary\|ask\|mark}` | `{taskId, state:"reserved"}`（LLM/RAG 接入后填结果） |
| POST | `/api/diarize` | `{audio}` | 单段音频直接分离（不建会议，给眼镜/调试用） |

## 6. 参数（环境变量）

| 变量 | 默认 | 含义 |
|---|---|---|
| `AR_DIAR_SEG_MODEL` | `models/diarization/pyannote-segmentation-3.0.onnx` | 分段模型；不存在则退回能量 VAD |
| `AR_DIAR_MERGE_SIM` | `0.75` | 同人聚类阈值；实测同人 ≥0.82、异人 ≤0.67 |
| `AR_DIAR_MAX_SPEAKERS` | `8` | 最多分几个人（防"一句话一个人"） |
| `AR_DIAR_MIN_SEG` | `0.8` | 短于该时长的段不单独聚类，聚完贴到最近的簇 |
| `AR_DIAR_MIN_SPEAKER_SEC` | `1.0` | 总时长不足该值的簇视为碎片，强制并入最近簇 |
| `AR_DIAR_GAP` | `0.35` | 相邻同人段合并间隔 |
| `AR_DIAR_MIN_ON` / `AR_DIAR_MIN_OFF` | `0.3` / `0.5` | 分段的语音/静音最短时长 |
| `AR_DIAR_OVERLAP` | `drop` | 重叠策略：`drop` 整段丢 / `trim` 截掉重叠部分 |
| `AR_DIAR_OVERLAP_TOL` | `0.12` | 判定重叠的时间容差（秒） |
| `AR_MEETING_DIR` | `data/meetings` | 会议数据目录 |
| `AR_MEETING_MAX_SECONDS` | `1800` | 单场会议总时长上限（秒） |
| `AR_MEETING_MAX_CHUNKS` | `240` | 单场会议分片数上限 |
| `AR_MEETING_MAX_CHUNK_SECONDS` | `120` | 单个分片时长上限（秒） |
| `AR_MAX_BODY_BYTES` | `16777216`（16MB） | 单次 HTTP 请求体上限，超限 413 |
| `AR_MAX_AUDIO_BYTES` | `67108864`（64MB） | 单个音频输入上限 |
| `AR_MAX_IMAGE_BYTES` | `16777216`（16MB） | 单张图片输入上限 |
| `AR_ALLOW_LOCAL_FILES` | `1` | 是否允许**本机请求**传本地文件路径；远端始终只能用 base64/dataURL |
| `AR_VOICE_THRESHOLD` / `AR_VOICE_MARGIN` | `0.72` / `0.08` | 实名映射的阈值（沿用 v2） |
| `AR_ASR_PROVIDER` | `off` | `off/aliyun/tencent/volcano`，云端转写预留 |

```text

# 回归（原有功能）：api_test 14 / api_console 15 / voice_api_test 13 / glasses_sim 全部通过
```

- 3 人测试会议（35.8s，3 人 × 2 句）：分离出 3 人，**零串号**，簇→实名全部正确。
- 整场 finalize 耗时 ≈ 4.1–4.5s（含分段 + 逐段声纹 + 聚类 + 映射）。
- 单段音频 `POST /api/diarize`：正确识别 1 人。
- 追加第 7 个分片后重新 finalize 仍是 3 人（已修：0.5s 碎片曾被误判为第 4 个人）。

## 8. 局限与下一步

**当前局限**

1. **重叠说话按垃圾处理**：默认 `drop` 整段（`dropped_overlap` 计数），不参与聚类；需要保留重叠内容时改 `AR_DIAR_OVERLAP=trim`，或另接 overlapped-speech 模型。
2. **未知人数**靠阈值 + 上限；人越多越吃聚类参数，正式会议建议先给 `max_speakers`。
3. **不是流式**：现在 `finalize` 一次性算整场；边说边出 spk 需要增量聚类 + 滚动窗口。
4. **没有转写**：`segments[].text` 目前为空；接 ASR 后由 `asr.attach_text()` 按时间重叠贴回。
5. **远场/噪声**：测试集是干净语音；真实会场建议加降噪、VAD、增益归一化。

**下一步（按优先级）**

1. **接 ASR**：配 `AR_ASR_PROVIDER=aliyun|tencent|volcano` + key，跑通 `transcript` 的 `text`。（或离线 FunASR）
2. **按键指令**：`/api/v1/action/trigger` 的 summary/ask/mark 接 LLM / RAG，出纪要卡片。
3. **眼镜端会议模式**：连续采集分片（注意 `input.audio` 单会话 60s 上限，需要重开会话），上传后轮询，`/api/latest` 显示会议卡。
4. **控制台会议页**：创建会议、上传/录音、看 speakers、点 spk 绑实名（现在只有 API）。
5. **增量/实时**：滚动窗口聚类 + 相邻段平滑，把延迟从"整场"降到"每 10–20s"。

## 9. 隐私

- 全部离线：音频只落在本机 `data/meetings/`，`*.wav` 与 `meta.json` 可直接删除。
- `data/meetings/` 已加入 `.gitignore`，不会被误提交。
- 真人声纹属于生物特征：演示前确认对方知情同意；`bind` 的 `enroll` 默认 `false`，不会偷偷入库。
