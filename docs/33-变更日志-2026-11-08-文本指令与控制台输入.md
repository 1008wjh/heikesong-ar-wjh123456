## 做了什么

**1. 后端：把短文本当指令解析（确定性，不走模型）**

解析发生在 `node_ingest`（文本和转写后的语音都走这里），命中就绕过识别/抽取/提词，
直接出卡；不命中才走原来的流程。

| 输入 | 效果 |
|---|---|
| `换成Lena` / `不是他，是Lena` | 换当前人，返回她的档案卡，`matched_by=text` |
| `不是他` / `认错了` | `待确认`：问换成谁 |
| `就是他` | 确认当前人，回到完成态 |
| `只看待办` / `只保留日期` / `筛选报价单` | `layout=focus`，只留匹配要点 |
| `优先日期` / `先看承诺` | 匹配项排最前，其余保留 |
| `显示全部` / `回到刚才` | 回到人物档案卡 |
| `取消` / `不要了` | `异常 · 已取消` |

配套：

- **纠正会粘住**：`_PIN[session] = 新的人`，`run_feed` 优先用它；
  眼镜端下一片还带旧 `person_id` 也不会被改回去。
- **指令不写档案**：`node_commit` 对指令直接跳过，避免"只看待办"被写成对话记录。
- **歧义**：名字匹配到多个人时返回 `待确认`，列出候选，不瞎选。
- **日志**：每次指令写一行 `text.command`（cmd/arg/person/state/ms）。
- `/api/latest` 增加 `session` 字段（同一个接口，不是新接口），控制台靠它找到当前会话。

**2. 控制台：右下角「对眼镜说一句」**

- 每 2.5 秒拉一次 `/api/latest`：`kind=agent` 且 30 分钟内 → 显示「在线 · g-xxx」，否则「待机」并禁用发送；
- 输入框 + 发送（回车也行）+ 4 个快捷 chip：只看待办 / 优先日期 / 显示全部 / 不是他；
- 结果行显示 `state · person · 前两行`，模型兜底会标「（模型兜底）」；
- 发送后眼镜端用现有轮询把新卡刷出来，不需要新增推送通道。

## 边界

- 不新增接口：只给 `/api/latest` 加了 `session` 字段；
- 不改眼镜包：仍是 3.5.5 / 77，文本结果靠轮询上屏（约 0.7 秒）；
- 控制台只跟"最近一个会话"；多段并发不支持；
- 镜片键盘字符有限，现场演示用控制台输入。
