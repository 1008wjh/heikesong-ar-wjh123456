# 任务 2：多人会议架构与当前实现

> 状态：Phase 1.1 已落地（本地分人 + 会议图 + 五状态/四布局 + 文本指令 +
> 2/3 人确认 + 归档接口 + 眼镜端会议模式）。
> 单人流程不动；会议图独立。

## 1. 为什么独立会议图

单人图是“认人 + 档案”状态机，会议需要“分人 + 时间线 + 待办 + 归档”。
两者状态和节点顺序不同（会议必须先分人再逐段 ASR），所以：

- 复用叶子能力：`voice` / `llm` / `diarize` / `cards` / `store` / `calllog`；
- **不复用** `AgentState` / `node_ingest` / `node_identify` / `node_commit`；
- `src/agent.py:run_feed` 按 `mode=meeting` 分流到 `src/meeting_agent.py`。

## 3. 会议图

```text
START
  └─ mtg_ingest      # 解码、时长/峰值、slice_no；文本指令不推进切片
       └─ mtg_commands   # 文本指令：人数/绑定/布局/确认
            └─ mtg_diarize    # pyannote + CAM++，失败→单说话人
                 └─ mtg_merge     # 跨切片质心匹配；新人→“发言人N”
                      └─ mtg_asr       # 按段逐段转写（最多 24 段/片）
                           └─ mtg_actions   # 规则抽待办 + 去重（最多 8 条）
                                └─ mtg_summary   # 会议摘要
                                     └─ mtg_view      # 五状态 + 四布局
                                          └─ END
```

MeetingState 关键字段：`session / meeting_id / slice_no / offset_sec / speakers[] /
segments[] / actions[] / transcript / summary / layout / confirmed / expected_speakers /
command / view / degraded`。

## 4. 发言人注册表

- 每片 diarize 得到 spk + 192 维质心；
- 与 `speakers[]` 质心余弦匹配（阈值 0.72）；
- 匹配上：累加时长、EMA 更新质心、沿用名字；
- 匹配不上：新建 `spk_mtg_N`，名字“发言人N”；
- 用 CAM++ 对人脉库匹配一次，高分才显示真名；
- **不自动写人脉库**；只有用户确认才绑定 `person_id`。

## 5. 存储（没有数据库）

- 热状态：LangGraph `MemorySaver`，每个会议 session 一个 thread；
- 冷数据：每片结束写 `data/meetings/agent_<session>/meta.json`；
- 原子写（`.tmp` + `os.replace`）；
- 归档 `POST /api/agent/archive` 写最终 `status=archived`；
- 不上 SQLite：延迟不在存储，量级也小；以后要检索再换 `meeting_store` 实现。

## 6. 接口

```text
POST /api/agent/feed
  { session, audio?, text?, mode:"meeting", manual?:false }
  -> { view: { state, layout, rows, speaker_count, speakers, action_count,
                actions, options, summary, confirmed, expected_speakers,
                mode:"meeting", degraded }, rev, ms }

POST /api/agent/archive
  { session }
  -> { ok, meeting_id, speaker_count, action_items, summary, path }
```

## 7. 五状态与四布局

| 状态 | 触发 | 镜片行为 |
|---|---|---|
| 待命 | 刚进会议、还没有音频 | 提示按一下开始听、可用文本指令 |
| 处理中 | 有音频但还没分出发言人 | 显示“会议中…/还没听到明确人声” |
| 待确认 | 检测到 ≥2 人且用户还没确认 | 显示“检测到 N 人 · 确认参会人”，等确认 |
| 完成 | 已确认人数，或只有 1 人 | 显示人数/姓名/待办/段数，可切布局 |
| 异常 | 图执行抛错 | 显示错误摘要 + 可选操作 |

布局：

- `meeting`（full）：默认会议卡；
- `meeting_focus`：只看待确认待办；
- `meeting_compact`：按负责人分组；
- `meeting_advice`：下一步建议。

文本指令（`text` + `mode=meeting`，走同一个 session）：

| 说法 | 效果 |
|---|---|
| `确认人数` / `确认` / `保存` | 锁定本场人数；状态转“完成” |
| `改人数 3` / `3 人` / `三人` | 记录预期人数，用于人数对不上提示 |
| `第二位是王姐` / `这是王姐` / `换成王姐` | 把第 N 位发言人绑定到真实姓名 |
| `只看待确认` / `待办` | 切 focus |
| `按负责人` / `分组` | 切 compact |
| `给我建议` / `建议` | 切 advice |
| `回到全部` / `全部` | 回 full |

未知指令会把“没听懂 + 可用词”写进 `notes`，并在布局页显示最后一条。

## 8. 眼镜端

- 模式选择：多人提示改为“2 人以上 · 分人 / 待办 / 归档”；
- 第一片 15 秒自动（认人/分人），之后会议模式每 55 秒自动切片；
- 单人模式仍保持“第一片后手动确认”；
- 会议录音中按返回：先等队列真正传完，再走 `/api/agent/archive`，显示
  “会议已保存 · N 人 / M 条待办”；
- 会议录音中按确认：手动切最近 1.5 秒追问；上键=短语键盘，下键=当前 options；
- 会议结束后 `lastMeeting` 保留，仍可用文本指令回看/切布局；开始单人会话时清空。

实测补充：

- 3 人 demo（35.8s）：3 人 / 6 段首片，5.0s；同一 session 第二片不重复长人，归档 12 段。
- 2 人截取（12.63s）：2 人 / 670ms，确认后归档 2 人。
- 静音：`处理中` / 0 人，不崩。
- 55 秒切片：3 人 / 4481ms，归档正常。
- 真实 WSL 模拟器：`irisview run` 可出 Client + Mono 两个窗口，镜片 idle 为
  “● MemoryLens / 按一下开始听…”，无默认 `Text`；会议录音交互仍以
  `meeting_glasses_sim.js` 为主回归。

## 11. 设计原则

- 会议实时链路不碰数据库；
- 每片只写一次 JSON；
- 旧结果按 slice/rev 作废（下一阶段补）；
- 分人失败按单说话人兜底；
- 单人流程不被会议改动影响。
