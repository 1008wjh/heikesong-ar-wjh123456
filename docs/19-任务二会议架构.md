# 任务 2：多人会议架构与当前实现

> 状态：Phase 0/1 已落地（本地分人 + 会议图 + 归档接口 + 眼镜端会议模式）。
> 单人流程不动；会议图独立。

## 1. 为什么独立会议图

单人图是“认人 + 档案”状态机，会议需要“分人 + 时间线 + 待办 + 归档”。
两者状态和节点顺序不同（会议必须先分人再逐段 ASR），所以：

- 复用叶子能力：`voice` / `llm` / `diarize` / `cards` / `store` / `calllog`；
- **不复用** `AgentState` / `node_ingest` / `node_identify` / `node_commit`；
- `src/agent.py:run_feed` 按 `mode=meeting` 分流到 `src/meeting_agent.py`。

## 2. 代码结构

```text
src/

  meeting_store.py   # data/meetings/agent_<session>/meta.json 原子写

  meeting_agent_test.py  # 会议 API 最小回归（3 人 + 归档）

```

## 3. 会议图

```text
START
  └─ mtg_ingest      # 解码、时长/峰值、slice_no
       └─ mtg_diarize    # pyannote + CAM++，失败→单说话人
            └─ mtg_merge     # 跨切片质心匹配；新人→“发言人N”
                 └─ mtg_asr       # 按段逐段转写（最多 12 段/片）
                      └─ mtg_actions   # 规则抽待办 + 去重
                           └─ mtg_view      # meeting view / 五状态
                                └─ END
```

MeetingState 关键字段：`session / meeting_id / slice_no / offset_sec / speakers[] /
segments[] / actions[] / transcript / view / degraded`。

## 4. 发言人注册表

- 每片 diarize 得到 spk + 192 维质心；
- 与 `speakers[]` 质心余弦匹配（阈值 0.72）；
- 匹配上：累加时长、EMA 更新质心、沿用名字；
- 匹配不上：新建 `spk_mtg_N`，名字“发言人N”；
- 用 CAM++ 对人脉库匹配一次，高分才显示真名；
- **不自动写人脉库**；只有用户确认才绑定 `person_id`。

## 5. 存储（没有数据库）

- 热状态：LangGraph `MemorySaver`，每个会议 session 一个 thread；
- 冷数据：每片结束写 `data/meetings/agent_<session>/meta.json`；
- 原子写（`.tmp` + `os.replace`）；
- 归档 `POST /api/agent/archive` 写最终 `status=archived`；
- 不上 SQLite：延迟不在存储，量级也小；以后要检索再换 `meeting_store` 实现。

## 6. 接口

```text
POST /api/agent/feed
  { session, audio, mode:"meeting", manual?:false }
  -> { view: { state, layout:"meeting", rows, speaker_count, action_count,
                actions, options, mode:"meeting" }, rev, ms }

POST /api/agent/archive
  { session }
  -> { ok, meeting_id, speaker_count, action_items, path }
```

## 7. 眼镜端

- 模式选择：多人提示改为“三人以上 · 分人 / 待办 / 归档”；
- 第一片 15 秒自动（认人/分人），之后会议模式每 55 秒自动切片；
- 单人模式仍保持“第一片后手动确认”；
- 返回键结束：会议走 `/api/agent/archive`，显示“会议已保存 · N 人 / M 条待办”。

## 9. 验证

```text
python test/diarize_test.py          # 29 passed
python test/meeting_agent_test.py    # 3 人 / 12 段 / 归档通过
python test/agent_test.py            # 单人回归 10 passed

```

实测补充：

- 3 人 demo（35.8s）：3 人 / 6 段首片，5.0s；同一 session 第二片不重复长人，归档 12 段。
- 2 人拼接音频：2 人 / 670ms。
- 静音：`处理中` / 0 人，不崩。
- 55 秒切片：3 人 / 4481ms，归档正常。

## 10. 设计原则

- 会议实时链路不碰数据库；
- 每片只写一次 JSON；
- 旧结果按 slice/rev 作废（下一阶段补）；
- 分人失败按单说话人兜底；
- 单人流程不被会议改动影响。
