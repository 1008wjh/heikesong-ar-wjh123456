## 你看到的现象怎么来的

自动建号的陌生人，本来只应该有：名字（陌生人X）+ 声纹 + 一句"眼镜端自动建的"说明。
但实际还有两处会往里写：

1. **`node_commit` 每次对话都会合并要点**
   `store.merge_facts()` 把模型从转写里抽出来的「对话要点」写进
   `complex["对话要点"]`，并把这段原文写进 `conversations`。
   如果转写有误或模型自由发挥，这些内容看起来就是"凭空冒出来的详细资料"。

2. **老记录迁移会合成简单数据**
   自动建号时没有显式写 `simple` 字段，`store._migrate()` 下次加载时会用
   `role` / `info` 合成 `simple = {"身份": "陌生人", "信息1": "眼镜端自动建的…"}`。

## 改法

- 建号时显式给空：`simple={}, complex_={}`（三个建号入口都改了）；
- `merge_facts` 遇到名字以「陌生人」开头的记录：**只更新 `last_met`**，
  不写对话要点、不存对话原文；
- 在控制台把名字改掉（或补了资料）之后，名字不再以「陌生人」开头，
  下一次对话就会正常积累 —— 相当于"人工确认后才开始记"。

## 验证

`test/agent_test.py` 新增 3 条（全部通过）：

```
ok  陌生人的简单/复杂数据是空的
ok  陌生人不会被自动写详细数据
ok  陌生人也不会被自动写对话记录
```

手动验证"确认后恢复"：

```
创建 陌生人B → 改名「测试小周」→ 再聊「我下周三去上海出差，回来再聊」
complex = {"对话要点":{"日期":"下周三去上海出差","跟进":"出差回来后再联系"}}
```

`glasses_sim` / `meeting_glasses_sim` 全绿（自动建号的镜片提示不变）。

## 说明

- 判断"是否已确认"用的是名字前缀「陌生人」；如果你想把"陌生人"当正式名字用，
  告诉我，我改成显式的 `auto` 字段。
- 之前已经建过的陌生人如果还在库里，改名后就会恢复正常积累；
  当前库里没有残留的陌生人记录（55 人都是正式记录）。
