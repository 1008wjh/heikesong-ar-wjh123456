## 现象

点「提词」后，模型其实正常返回了结果，但中途镜片会整页闪一下类似
「后台在跑 · 这次慢 / 这次有点慢，再按一次确认」的页面，几秒后才回到在听/卡片。

## 根因

1. 眼镜端每 700ms 轮询一次 `/api/latest`，超时 1.5 秒。
   后端在跑 ASR / 大模型的时候请求会排队，超过 1.5 秒就抛超时。
2. `poll()` 的 `catch` 直接调 `paintOffline()`，而 `paintOffline` **没有** capture 守卫
   （`paintIdle` 有），于是正在「在想…」的整屏被换成了报错页：
   `后台在跑 · 这次慢 / 这次有点慢，再按一次确认`。
3. 报错页画完不更新 `listenSig`，下一拍 `tick()` 里的 `paintListening()` 认为
   「指纹没变」直接 return —— 所以这一页不会立刻被刷掉，要等状态真的变化才恢复，
   看起来就是"闪了几秒"。

测试日志能直接看到这个超时风暴：

```
[poll] The operation was aborted due to timeout
[poll] fetch failed
...（识别人/ASR/模型跑的时候连着出现）
```

## 改法

- `poll()` 失败时：如果正在听、正在想，或者刚结束 45 秒内（还在整理归档），
  只 `console.log`，**不画整页**。真正的失败由按钮那次请求自己报。
- `paintOffline()` 加 capture 守卫：录音期间只把状态行闪成「后台有点慢 · 稍等」，
  按钮和卡片留在原地。
- 状态行优先级改成「临时提示 > 在想…」：这样提示能被看到，而不是被"在想…"盖住。
- 回归测试：在提词等待期间人为注入一次 `/api/latest` 超时，断言镜片上没有「后台」字样，
  并确认回复仍然到达。

## 实测

```

[poll] timeout
ok  轮询超时不闪「后台」整页        在想…（画面没变）

```
