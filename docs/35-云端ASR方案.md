# 云端 ASR 接入方案（火山优先，本地兜底）

> 目标：会议实时转写优先走云端 ASR，识别率/标点/中英混合更好；云端超时、断网、额度不足时自动回退本地 SenseVoice。
> 本地模型只做兜底，不再作为默认路径。

## 1. 结论

方向是对的，但要把两件事分开：

1. **转写（ASR）**：可以云优先，本地兜底；
2. **分人（speaker diarization）**：普通“一句话识别”不返回说话人，不能直接替代本地 CAM++/pyannote。
   - 如果火山接口支持“会议转写/说话人分离”，可以让它同时返回 speaker；
   - 如果不支持，保留本地分人，只把每个 speaker 片段的 ASR 换成云端。

不要把“云端 ASR”理解成“云端连分人也一起解决”，否则会出现文字准了、说话人仍乱的情况。

## 2. 接口选择

火山引擎语音识别有三类：

| 类型 | 适合 | 备注 |
|---|---|---|
| 一句话识别（HTTP） | 当前 6–8 秒切片 | 接入最简单，适合先做 PoC |
| 流式识别（WebSocket） | 真正实时字幕 | 延迟最低，但要长连接/重连 |
| 录音文件识别 | 会后总结/离线归集 | 准确率最高，可带回说话人（以接口能力为准） |

建议顺序：

1. 先用**一句话识别**替换当前每片 ASR，验证错别字是否明显下降；
2. 再把会议实时链路换成**流式识别**；
3. 停录后的离线归集用**录音文件识别 + 说话人分离**，修正整场结果。

## 3. 需要的配置

```bat
set "AR_ASR_PROVIDER=volcengine"
set "AR_VOLC_APP_ID=..."
set "AR_VOLC_TOKEN=..."
set "AR_VOLC_CLUSTER=..."        REM 按控制台的中英混合/会议模型填
set "AR_VOLC_SECRET=..."         REM 如果接口需要
set "AR_VOLC_TIMEOUT=4"
set "AR_ASR_FALLBACK=local"      REM 云端失败回退本地
```

具体字段名以火山控制台当前 API 文档为准；需要你提供 AppID / Access Token / Cluster / Secret。

## 4. 代码接入点

现有 `src/llm.py` 已有 `transcribe()` 和 `AR_ASR_PROVIDER`：

```text
meeting_service.feed
  → meeting_agent（分人 + 切片）
  → llm.transcribe(segment_wav)
  → 本地 SenseVoice / HTTP ASR
```

改法：

1. `llm.transcribe()` 增加 `provider == "volcengine"` 分支；
2. 云端调用失败/超时/空文本 → 自动走现有本地 SenseVoice；
3. 每片记录 `asr_provider`、`asr_ms`、`fallback`，控制台/详情可查；
4. 如果云端返回标点/热词，优先使用云端文本；本地只补空结果，不重复拼接。

## 5. 分人怎么处理

- 保留 `diarize.py` 的 CAM++ 分人；
- 对每个分人片段单独送云端 ASR（短音频，准确率高，但调用次数多）；
- 或使用火山的会议转写接口，一次返回 speaker + 文本，再与本地时间轴对齐；
- 停录后跑一次整场“录音文件识别 + 说话人分离”，用最终结果覆盖/校正实时文本。

## 6. 风险

- 会议音频会上传到云端，需用户知情/同意；
- 云端延迟和网络抖动会影响实时体验，必须设 3–5 秒超时并回退；
- 云端按量计费，切片越短调用越多；
- 中英混合要选对应模型/热词库，否则专有名词仍会错；
- 分人仍建议本地兜底，云端 speaker 能力要先确认。

## 7. 建议落地顺序

1. 拿到火山凭证，先用一句话识别替换 8 秒切片 ASR；
2. 用同一段会议音频对比本地/云端错字率；
3. 通过后接流式识别；
4. 最后做停录后的会议转写 + 分人校正。

没有凭证前，不建议先改主链路；可以先加 `AR_ASR_PROVIDER=volcengine` 的接口骨架和本地回退开关。
