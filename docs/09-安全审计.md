## 一、已修复的问题

| # | 严重度 | 问题 | 证据 | 修复 |
|---|---|---|---|---|
| 1 | **高** | 静态文件前缀绕过：`startswith(WEB)` 没带路径分隔符，`webx/` 等同前缀目录可被读 | 实测 `GET /../webx/secret.txt` → **200 PREFIX-BYPASS** | `_safe_static()` 用 `realpath` + `commonpath` 校验；路径穿越/软链逃逸返回 404；新增 `test/security_test.py` |
| 2 | **高** | 任意本地文件读取：接口接受绝对路径，远端的 `POST /api/v1/audio/upload {"audio":"C:\\...\\x.wav"}` 会把任意 WAV 读进会议并可回放 | 实测上传 `test/voice/huihui_a.wav`（数据目录外）→ 200，`/api/v1/audio/play` 回放出 96KB WAV | 本地路径只允许**本机请求**（`_local()`），远端只能用 base64/dataURL；`AR_ALLOW_LOCAL_FILES=0` 可彻底关闭；新增单文件大小上限。**注意**：如果前面挂了本机反向代理，`client_address` 会变成 127.0.0.1，此时应设 `AR_ALLOW_LOCAL_FILES=0` |
| 3 | **高** | 服务端多线程下声纹模型懒加载竞态：并发请求可能拿到 `_lock=None` 崩溃 | 代码走查 | `voice._get_extractor()` 加 `_init_lock` 双检锁 |
| 4 | 中 | 请求体无上限：`Content-Length` 多大就读多大，可内存 DoS | 实测 2MB JSON 被接受 | `AR_MAX_BODY_BYTES`（默认 16MB），超限返回 **413**（读 body 前拒绝） |
| 5 | 中 | 会议无资源上限：分片数/总时长/单片时长无限，磁盘与 `finalize` 内存可被吃满 | 代码走查 | `AR_MEETING_MAX_SECONDS=1800`、`AR_MEETING_MAX_CHUNKS=240`、`AR_MEETING_MAX_CHUNK_SECONDS=120`，超限 500 并给明确错误 |
| 6 | 中 | `GET` 未捕获异常：查询不存在的会议时直接断连接，客户端 `RemoteDisconnected` | 实测 | `do_GET` 统一包装，返回 JSON 500 |
| 7 | 中 | 慢连接/半截请求可无限占用线程（slowloris） | 代码走查 | `Handler.timeout = 30` |
| 8 | 中 | Docker 部署时会议数据落在容器内 `/app/data/meetings`，`/data` 卷只持久化了人脉库 | 代码走查 | `Dockerfile.backend` / `docker-compose.yml` 增加 `AR_MEETING_DIR=/data/meetings` |
| 9 | 中 | 声纹质心（192 维生物特征）写进 `meta.json`，贴日志/分享会泄露 | 代码走查 | 质心单独存 `centroids.json`，`meta.json` 可安全分享 |
| 10 | 中 | `enroll: "false"` 字符串被 `bool()` 判成 True，误把声纹入库 | 实测 | `_as_bool()` 严格解析 |
| 11 | 低 | `seq` 缺省用 `len(chunks)+1`，有空洞/删除时撞号；`seq=0/负数` 可写入 | 代码走查 | `max(seq)+1` + 整数/≥1 校验 |
| 12 | 低 | 回放 `timestamp=-1`、非数字参数异常 | 实测 | 负值钳 0，`before/after` 限制 0–30s，非数字明确报错 |

## 二、审计初版未修复清单（部分已在本轮修复，状态以 [10-问题清单](10-问题清单.md) 为准）

### P0（仅当部署到公网/不可信局域网时）

1. **无鉴权/授权**：所有 `/api/*`（含 `/api/people`、`/api/photo`、`/api/v1/audio/play`、`DELETE /api/v1/session/{id}`）无需任何凭据。任何能访问 8765 的人都能读人脉库、看照片、听会议录音、删数据。
   - 建议：默认绑定 `127.0.0.1`；需要局域网时加 `AR_API_TOKEN` + `Authorization` 校验，或交给 Nginx 反代做 Basic/JWT。
2. **无 TLS**：音频、声纹、照片、会议内容明文传输。
   - 建议：反代 HTTPS（Caddy/Nginx），或只在回环地址监听 + SSH 隧道。

### P1（建议在答辩/上线前处理）

3. **生物特征数据进了 git**：`data/people.json`（含王姐 1 条 192 维声纹）与 `data/photos/*.jpg` 被仓库跟踪。公开仓库涉及隐私/合规。
   - 建议：`git rm --cached data/people.json data/photos/*`，加入 `.gitignore`，提供 `people.example.json`；历史提交需 `git filter-repo` 才能彻底清除。
4. **CSRF**：服务端不校验 `Content-Type`，恶意网页可用 `text/plain` 简单请求（无 preflight）触发有副作用的 POST。当前无鉴权，风险被"本来就能直接调"掩盖；加鉴权后必须同时修。
   - 建议：要求 `Content-Type: application/json`，加 `X-Requested-With` 或 token。
5. **错误信息回显**：500 返回 `type(e).__name__: e`，可能包含路径/内部细节（如 `file does not start with RIFF id`）。
   - 建议：生产环境 `AR_DEBUG_ERRORS=0`，只回通用错误码。
6. **依赖未锁版本**：Dockerfile 用 `numpy>=2.0` 等浮动版本，重建镜像不可复现，供应链风险。
   - 建议：提交 `requirements.lock`（或固定到具体版本 + hash）。
7. **无速率/并发上限**：`ThreadingHTTPServer` 来多少连接开多少线程；大并发可打满 CPU/内存。
   - 建议：反代限流，或加信号量限制并发。

### P2（功能/运维不足）

8. **`finalize` 内存 O(n)**：30 分钟音频约 115MB float32，加上分段副本与声纹，小内存机器可能 OOM。
   - 已设 30 分钟上限；进一步需流式/分块 diarization。
9. **重叠语音直接丢弃**：符合当前"轮流说话、重叠=垃圾"的需求，但会丢信息；需要时可改 `AR_DIAR_OVERLAP=trim` 或接 overlapped-speech 模型。
10. **没有 ASR**：`segments[].text` 为空，`/api/v1/action/trigger` 仍是 `reserved`。
11. **固定测试端口**：`8765/8798/8799`，并行跑测试会冲突。
12. **模型许可未逐条核对**：CAM++（3D-Speaker，Apache-2.0）与 pyannote segmentation 模型需商用前核对 HF 模型条款。
13. **MiMo 外发**：`AR_USE_LLM=1` 时人物笔记会发到 `api.xiaomimimo.com`；默认关闭，演示前确认。
14. **Docker 端口绑定所有网卡**：`"8765:8765"`；本地演示建议 `"127.0.0.1:8765:8765"`。
15. **日志含 PII**：`[voice] ... -> 王姐` 会写人名/相似度；分享日志前清理。

## 四、建议处置顺序

1. **答辩/演示前**：确认只在本机或可信内网运行（防火墙/绑定 127.0.0.1）。
2. **公开仓库前**：处理 `data/people.json` + 照片的隐私问题。
3. **要联网演示**：加 token + HTTPS + 限制 8765 监听地址。
4. **长期**：ASR 接入、流式 diarization、依赖锁定。
