## 1. P0 —— 联网部署前必须处理

### P0-01 无鉴权：任何能访问 8765 的人都能读/删你的数据

- **状态**：✅ 已修复（`AR_HOST` 默认 127.0.0.1；`AR_API_TOKEN` 校验 X-API-Token/Bearer；控制台 401 提示 token；眼镜 `MEMORYLENS_TOKEN`；`test/auth_test.py` 17 项）
- **位置**：`src/server.py` 所有 `/api/*`；启动默认 `AR_HOST=127.0.0.1`（要局域网才改 0.0.0.0）
- **问题**：接口没有任何 token/cookie/密码校验。
- **能做什么（实测）**：
  - `GET /api/people` 直接拿到全部联系人（姓名、身份、备注、照片路径）；
  - `GET /api/photo?id=...` 看照片；
  - `GET /api/v1/audio/play?sessionId=...` 听会议录音；
  - `POST /api/people/delete`、`DELETE /api/v1/session/{id}` 删数据。
- **为什么会这样**：这是黑客松内网 Demo 的取舍，服务端默认监听所有网卡。
- **影响**：同一 WiFi 下任何人（包括隔壁赛场）都能读到你的人脉库和会议内容；公网等于把生物特征数据库公开。
- **建议修法（按成本从低到高）**：
  1. 只监听本机：`AR_HOST=127.0.0.1`（代码目前写死 `0.0.0.0`，需要加环境变量）；
  2. 最小 token：`AR_API_TOKEN`，校验 `Authorization: Bearer ...`；`/api/health` 可放行；
  3. 正式方案：Nginx/Caddy 反代 + Basic/JWT + HTTPS。
- **验收**：不带 token 请求 `/api/people` 返回 401；带 token 返回 200。

### P0-02 无 TLS：音频、声纹、照片明文传输

- **状态**：✅ 已修复（`AR_TLS_CERT`/`AR_TLS_KEY` 原生 TLS；`tools/gen_self_signed_cert.py`；auth_test 有 HTTPS 实测）
- **位置**：部署层（`deploy/` / 反代）
- **问题**：HTTP 明文，眼镜端/网页/后端之间传 wav、JPEG、声纹。
- **影响**：同网段可抓包还原会议录音与照片；浏览器/客户端也无法确认服务器身份。
- **建议**：Caddy 自动 HTTPS 最省事；或 Nginx + 自签证书（真机需信任）；内网演示至少用 SSH 隧道。
- **验收**：`https://` 访问控制台；`curl http://` 不可用或被重定向。

## 2. P1 —— 答辩 / 公开仓库前建议处理

### P1-01 生物特征与照片被 git 跟踪（隐私/合规）

- **状态**：🔶 当前树已修复，**历史仍含旧数据**（`git log --all -- data/people.json data/photos` 还有 6 个提交）。要彻底清除需重写全部历史并 force push：脚本 `tools/purge_git_history.sh`（会二次确认），队友需重新 clone；**等你确认后再执行**。
- **位置**：`git ls-files data` → `data/people.json`、`data/photos/p_6f58be.jpg`、`data/photos/p_a0debb.jpg`
- **问题**：`people.json` 里有王姐的 1 条 192 维声纹；照片里有里奥/奥巴马。公开仓库 = 公开这些数据。
- **为什么发生**：为了"克隆即演示"，数据被提交进仓库。
- **影响**：违反"生物特征需单独同意"的常识；公开后即使删文件，历史提交仍可恢复。
- **建议**：
  1. `git rm --cached data/people.json data/photos/*.jpg`；
  2. `.gitignore` 加 `data/people.json`、`data/photos/`；
  3. 提供 `data/people.example.json`（空库）；
  4. 历史清理用 `git filter-repo --path data/people.json --invert-paths`（需重写历史，团队要先同步）。
- **验收**：新克隆的仓库没有真实人脸/声纹；控制台首次启动是空库。

### P1-02 CSRF：不校验 Content-Type，恶意网页可触发写操作

- **状态**：✅ 已修复（`_read_json` 强制 application/json → 415；**所有** POST/DELETE 都过 `_check_csrf()`（含无 body 请求），跨站/Origin 不匹配 → 403；auth_test 覆盖）
- **问题**：浏览器跨站 `fetch(..., {body:'{"name":"x"}', headers:{'Content-Type':'text/plain'}})` 属于"简单请求"，不会触发 CORS 预检，服务端仍按 JSON 解析并执行。
- **影响**：用户打开恶意网页时，页面可静默新增/删除联系人、建会、删会议（当前无鉴权，风险被掩盖；一旦加 token/cookie，这条会变成真 CSRF）。
- **建议**：强制 `Content-Type: application/json`（否则 415）+ 校验 `Origin`/`Sec-Fetch-Site` + token。
- **验收**：`text/plain` 的 POST 返回 415；带正确 Content-Type 的请求正常。

### P1-03 依赖未锁定，镜像不可复现 / 供应链风险

- **状态**：⏸ 按你的要求本轮不改（保留原样）
- **位置**：`deploy/Dockerfile.backend`（`numpy>=2.0`、`opencv-python-headless>=4.10`、`onnxruntime>=1.19`、`sherpa-onnx>=1.10`）；仓库无 `requirements.txt/lock`
- **问题**：每次 `docker build` 可能装到不同版本；某次上游发版可能直接改变识别效果或破坏 API。
- **影响**：今天能跑的镜像，明天重建可能失败；答辩现场重建有风险。
- **建议**：生成 `requirements.lock`（pip freeze）并固定版本（最好带 hash）；Dockerfile 改为 `-r requirements.lock`。
- **验收**：两次干净构建得到相同版本；`pip check` 无冲突。

### P1-04 Docker 端口绑定所有网卡

- **状态**：✅ 已修复（compose 改为 `127.0.0.1:8765:8765`；容器内 `AR_HOST=0.0.0.0` 仅用于端口映射）

- **影响**：同一局域网可访问（与 P0-01 叠加就是"裸奔"）。
- **建议**：本地演示改 `"127.0.0.1:8765:8765"`；需要手机/眼镜连时再显式改为局域网 IP，并同时加 token。

## 3. P2 —— 质量 / 性能 / 运维

### P2-01 错误信息回显内部细节

- **状态**：✅ 已修复（未预期异常默认只回 `internal_error`；`AR_DEBUG_ERRORS=1` 才回显；业务校验错误保留可读信息）
- **问题**：500 会把异常类型、文件解析错误、路径等信息回给调用方。
- **影响**：信息泄露；也给攻击者调试服务的便利。
- **建议**：`AR_DEBUG_ERRORS`（默认 0）控制是否回显；生产只回 `{"ok":false,"error":"internal_error"}` + 日志留详情。

### P2-02 无速率/并发限制

- **状态**：⬜ 待处理
- **位置**：`ThreadingHTTPServer`（632 行），无并发上限、无限流
- **问题**：来多少连接开多少线程；`finalize` 单次 4.5s 且持锁，重复调用可打满 CPU。
- **影响**：局域网内可被轻易 DoS；答辩时误操作也可能卡死。
- **建议**：反代限流；或服务端加信号量（如最多 4 个并发重任务）+ 每 IP 限速。

### P2-03 日志含 PII

- **状态**：✅ 已修复（默认只打 person_id；`AR_LOG_PII=1` 才打名字）
- **问题**：日志直接打印人名、相似度；会议 ID、路径也可能进日志。
- **影响**：日志被分享/上传 CI 时泄露联系人信息。
- **建议**：默认只打印 ID/相似度区间；`AR_LOG_PII=1` 才打印名字。

### P2-04 缺 `.dockerignore`，构建上下文含 `.git` 与生物特征数据

- **状态**：✅ 已修复（根目录 `.dockerignore` 排除 `.git`、`data/people.json`、`data/photos`、`data/meetings`、`test`、`docs`、`tools` 等）
- **问题**：整个仓库（`.git` 约 52MB、`data/people.json`、照片、测试 wav）都会作为 build context 发给 Docker daemon。
- **影响**：构建慢、占磁盘；生物特征数据被送进 daemon（虽然 Dockerfile 没 COPY，但上下文可见）。
- **建议**：加 `.dockerignore`：`.git`、`data/people.json`、`data/photos`、`data/meetings`、`test`、`tools`、`docs`、`*.md` 等。

### P2-05 `finalize` 非流式且全程持锁

- **状态**：⬜ 待优化
- **位置**：`src/meeting.py:234-236`（`with self._lock:` 包住整个分离过程）
- **问题**：35s 音频约 4.1–4.5s，期间同一会议的其它请求（bind/transcript）都要等；长会议更久。
- **影响**：控制台"转圈"，并发体验差；误以为服务卡死。
- **建议**：分离过程不持锁（先快照 chunk 列表，算完再写 meta）；或改成后台任务 + 轮询状态。

### P2-06 `finalize` 内存 O(n)

- **状态**：⬜ 待优化
- **位置**：`src/meeting.py._concat()` + `src/diarize.py`
- **问题**：把全部分片拼成一个 float32 数组，30 分钟约 115MB，再叠加分段/声纹临时对象。
- **影响**：小内存机器（4GB）可能 OOM；目前靠 `AR_MEETING_MAX_SECONDS=1800` 兜底。
- **建议**：流式/分块 diarization（按 5–10 分钟窗口 + 跨窗口说话人合并），或降低默认上限到 10 分钟。

### P2-07 相近声纹/噪声下可能并簇或串号

- **状态**：⬜ 待调优
- **位置**：`src/diarize.py`（贪心聚类 + 阈值 0.75；映射 0.72/0.08）
- **问题**：算法是阈值型：两个声音很像的人可能被并成一个；噪声段可能单独成簇（已有碎片并入兜底）。
- **影响**：真实会场（尤其同性/同年龄）人数可能少算；这是当前方案的主要精度风险。
- **建议**：用真实录音扫阈值；必要时换 ERes2NetV2/NeMo TitaNet embedding；或加"人数先验"。

### P2-08 无降噪 / AGC / 远场处理

- **状态**：⬜ 待优化
- **位置**：音频入口 `voice.read_wav` → 直接送模型
- **问题**：没有降噪、增益归一化、去混响。
- **影响**：嘈杂会场声纹质量下降，阈值失效。
- **建议**：加轻量降噪（如 noisereduce/RNNoise）或至少做峰值归一化；VAD 前置（Silero）。

### P2-09 会议音频/数据没有保留策略

- **状态**：⬜ 待处理
- **位置**：`data/meetings/`（已 gitignore，但本地会一直增长）
- **问题**：每场会保留 `meeting.wav` + 分片 + 质心，没有自动清理。
- **影响**：长期演示后磁盘满；生物特征音频长期留存。
- **建议**：加 `AR_MEETING_RETENTION_DAYS` 清理任务；或演示结束手动 `DELETE /api/v1/session/{id}`。

### P2-10 ASR 适配器"配了 key 就显示 ready"，但实际没实现

- **状态**：✅ 已修复（密钥齐全但实现未完成时状态为 `reserved`，不再假装 `ready`；多人链路优先走 `src/llm.py` 的 ASR）
- **问题**：配置了环境变量后 `asr.state` 显示 `ready`，但 finalize 一定进 `error`，状态误导。
- **影响**：排障时以为"已经接上了"。
- **建议**：未实现前把状态标成 `reserved`，或实现 HTTP 调用后再置 `ready`。

### P2-11 本地反代场景下"本地文件限制"会失效

- **状态**：🔶 部署注意（代码保留按 client_address 判断；**反代部署请设 `AR_ALLOW_LOCAL_FILES=0`**，docs/09 已标注）
- **问题**：若同机 Nginx 反代，远端请求的 `client_address` 也是 127.0.0.1，会被当成"本机"，从而允许传本地路径。
- **影响**：绕过 P0-01 之外的又一层防护。
- **建议**：反代部署时设 `AR_ALLOW_LOCAL_FILES=0`（已在 docs/09 标注）。
