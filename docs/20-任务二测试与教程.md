## 3. 会议是怎么跑的

```text
START
  ingest      解码 WAV、算时长/峰值；文本指令不推进 slice_no
  commands    文本指令：绑人 → 人数 → 布局 → 确认 → 未知提示
  diarize     pyannote 分段 + CAM++ 聚类（失败则单说话人兜底）
  merge       跨切片质心匹配（0.72）；新发言人 → spk_mtg_N
  asr         每段单独转写，最多 24 段/片
  actions     关键词规则抽待办，去重，最多保留 8 条
  summary     “N 人 · M 段 · K 条待办”
  view        五状态 + 四布局 + options
END
```

热状态在每个 `session` 的 LangGraph checkpoint；每片结束写一次：

```text
data/meetings/agent_<session>/meta.json
```

写盘是 `.tmp` + `os.replace` 原子替换；归档只改 `status=archived`，不删热状态。

## 4. 眼镜端操作教程

### 4.1 启动模拟器

WSL 里执行（把 `<WSL网关IP>` 换成 Windows 后端地址；通常是 `172.x.x.1`）：

```bash
cd /mnt/c/Users/lenovo/Desktop/heikesong-ar-wjh123456
export MEMORYLENS_BACKEND=http://<WSL网关IP>:8765
/home/iris/IrisView/Developer-Kit/bin/irisview run \
  dist/memorylens.fuiapp \
  --allow-debug-unsigned --display-mode mono --audio-mode desktop \
  --profile release --port 28045
```

取网关：

```bash
ip route show default | awk '{print $3}'
```

成功时出现两个窗口：

- `LLVISION Agent Platform`：Client 控制台；
- `LLVISION Agent Platform - Mono`：镜片画面。

镜片首屏应是：

```text
● MemoryLens
按一下开始听…
```

如果显示加载页/一片黑，先看第 8 节排错。

### 4.2 进入多人会议

1. 镜片首屏按一下开始；
2. 用上/下选到「多人会议」；
3. 按确认开始录音。

第一片 **15 秒**自动结束并分人；之后会议模式每 **55 秒**自动切一片。
全程不需要一直按确认。

### 4.3 五状态

| 状态 | 什么时候出现 | 镜片看到 | 你该做什么 |
|---|---|---|---|
| 待命 | 刚进会议，还没音频 | 会议待命 / 按一下开始听 | 开始说话 |
| 处理中 | 有音频，还没分出发言人 | 会议中… 还没听到明确人声 | 继续说，或等 1–5 秒 |
| 待确认 | 检测到 ≥2 人，尚未确认 | 检测到 N 人 · 确认参会人 | 说「确认人数」，或按确认 |
| 完成 | 已确认，或只检测到 1 人 | N 人 · 姓名 / 待办 / 已转写段数 | 说布局指令、绑人、返回归档 |
| 异常 | 图执行抛错 | 会议智能体出错了 + 摘要 | 看后端日志；返回重开 |

> “待确认”不再依赖“第一片”。第二片、第三片只要检测到 ≥2 人且没确认，
> 仍然保持待确认；确认之后才转“完成”。

### 4.4 四种布局

会议录音中或会议结束后，都可以用文本指令切换：

| 说法 | layout | 镜片内容 |
|---|---|---|
| `只看待确认` / `待办` | `meeting_focus` | 待确认待办，最多 4 条 |
| `按负责人` / `分组` | `meeting_compact` | 按负责人分组计数 |
| `给我建议` / `建议` | `meeting_advice` | 人数差、先追哪条、下一步 |
| `回到全部` / `全部` | `meeting` | 默认会议卡 |

布局页仍保留最后一条 `notes`，例如“已绑定王姐”“没听懂…”，避免指令像没反应。

### 4.5 文本指令怎么输入

会议录音中：

- 上键：打开短语键盘（方向键选字，确认键输入，删除/发送/关闭）；
- 下键：弹出当前 `options`，上下选，确认发送；
- 返回键：结束会议并归档。

会议结束后，`lastMeeting` 还保留当前会议 session，继续输入指令会落到同一场会议，
不会新建 `text-*` 会话。只有从未开过会议时，才新建普通文本会话。

### 4.6 确认 2 人 / 3+ 人

1. 第一片后看到“检测到 N 人 · 确认参会人”；
2. 如果检测人数不对，先说 `改人数 2` 或 `改人数 3`（也支持 `2 人`、`三人`）；
3. 说 `确认人数`、`确认`、`锁定` 或 `保存`；
4. 状态转“完成”，`confirmed=true`。

人数只影响提示和建议，不会强行删/加已检测到的发言人。
例如检测到 3 人、你说 2 人，会显示“人数 3≠2 · 说「改人数 3」”，提醒你改回来。

### 4.7 把发言人绑到真实姓名

会议卡只显示“发言人1/2/3”。三种说法：

```text
这是王姐
第二位是王姐
换成王姐
```

规则：

- 优先精确匹配人脉库姓名，其次允许包含匹配（至少两个字，避免“王”误配）；
- 匹配到人脉：显示真名并记 `person_id`；
- 人脉库没有：本场标记该名字，`person_id` 留空，**不自动写人脉库**；
- 绑定只改当前会议 checkpoint，不改 `data/people.json`。

### 4.8 返回归档

会议录音中按返回，眼镜端会：

1. 停止采集；
2. 等发送队列和正在处理的片全部完成（最多 45 秒）；
3. `POST /api/agent/archive {session}`；
4. 镜片显示“会议已保存 · N 人 / M 条待办”。

归档文件：

```text
data/meetings/agent_<session>/meta.json
```

字段包括 `meeting_id / session / status / speakers / segments / actions / summary /
degraded / created_at / archived_at`。

### 5.2 发一片会议音频

用 Python 发 `test/demo_meeting.wav`（避免 PowerShell 处理大 base64）：

```powershell

    "http://127.0.0.1:8765/api/agent/feed",
    data=json.dumps(body).encode(),
    headers={"Content-Type": "application/json"},

'@ | python -
```

Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/agent/feed `
  -ContentType "application/json" -Body $body | ConvertTo-Json -Depth 6

预期 `view.layout=meeting_focus`，`rows` 第一行是“待确认待办 · N 条”。

把 `text` 依次换成：

```text

回到全部

```

逐项检查 `layout`、`speakers[1].name`、`confirmed`、`state`。

### 5.4 归档并检查 JSON

```powershell
$body = @{ session = "manual-meeting-1" } | ConvertTo-Json
$r = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8765/api/agent/archive `
  -ContentType "application/json" -Body $body
$r | ConvertTo-Json -Depth 5
Get-Content $r.path -Raw
```

预期 `ok=True`，`speaker_count` 与会议卡一致，`path` 指向
`data/meetings/agent_manual-meeting-1/meta.json`。

### 5.5 `GET /api/latest`

`/api/latest` 是“眼镜空闲时轮询的最近一条”。它只反映单人/语音推送，
不要把“外部 POST 会议 feed 后空闲眼镜没变化”当成会议 bug：

- 会议录音过程中，眼镜端直接用 `/api/agent/feed` 的响应画卡；
- 只有会议结束后的文本指令仍走同一 session；
- 空闲时想验证会议卡，请用 `test/meeting_glasses_sim.js` 或真实录音。

## 8. 排错

### 8.1 后端连不上

```powershell
Get-NetTCPConnection -LocalPort 8765 -State Listen
Invoke-RestMethod http://127.0.0.1:8765/api/health
```

- 端口被旧进程占用：`Get-Process python | Stop-Process` 后重启；
- 眼镜端报 `fetch failed`：确认 `MEMORYLENS_BACKEND` 是 WSL 能访问的 Windows 网关，
  不是 `127.0.0.1`；
- Windows 防火墙首次弹窗要允许 Python 专用网络。

### 8.2 模拟器黑屏/加载页

现象：Client 停在“正在加载”，镜片只有 idle 或黑屏，端口 28045 起不来。

按顺序：

```bash
wsl --shutdown
```

等 10 秒，重新打开 WSL，确认：

```bash
ls /mnt/wslg/wayland-0 /mnt/wslg/.X11-unix/X0
```

再启动。仍失败时：

```bash
ps -ef | grep -E 'fusionui|irisview' | grep -v grep
```

用方括号模式杀旧进程，避免杀掉当前 shell：

```bash
pkill -f '[f]usionui-glasses-launcher'
pkill -f '[f]usionui-glasses-simulator'
```

再 `irisview run`。

### 8.3 包版本没变

FusionUI 用 `versionCode` 判断是否重装；只改 `version` 不递增 `versionCode`，
Client 会继续跑旧包，画面和 sha 完全不变。

当前：`glasses/FusionUIApp.json` 的 `version=3.1.0`、`versionCode=66`。
每次改代码重新打包前都要递增。

### 8.4 分人模型缺失

```text
models/diarization/pyannote-segmentation-3.0.onnx
models/campplus_zh_16k.onnx
```

缺 pyannote 时会议图会走“单说话人兜底”，不会崩，但 `speaker_count` 只有 1。
下载：

```powershell
python tools/fetch_diarization_model.py
```

### 8.5 转写为空

本地 ASR 模型默认在 `models/asr/`。缺模型时 `llm.transcribe` 返回空串，
会议仍有分人和段数，但 rows 里没有文字。检查：

```powershell
Get-ChildItem models\asr
```

按 `docs/07-IrisView-工具包.md` 的本地 ASR 章节补齐。

### 8.6 中文乱码

测试脚本输出乱码不影响断言。设置：

```powershell
$env:PYTHONIOENCODING="utf-8"
chcp 65001
```

### 8.7 `glasses_sim.js` 飘红

见 2.1：3 项单人旧问题。先跑 `meeting_glasses_sim.js` 确认会议链路，
不要把单人抖动算到会议验收里。
