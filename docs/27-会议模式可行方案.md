# 会议模式可行方案（以工作区文档 / 代码为准）

> **结论**：PRD V1.0 里有几处与工作区文档和实际代码冲突，不能按 PRD 做。
> 会议模式以 `docs/19-任务二会议架构.md`、`docs/20-任务二测试与教程.md`、
> `src/meeting_agent.py`、`glasses/src/index.js`（PRD 改动前）为准：
> **自动切片 + 五状态 / 四布局 + 文本指令 + 返回归档**。
> 在这个基线上补 **AI 回答**（会议文字检索 + DeepSeek API），
> **不做底部实时字幕、不强制云 ASR**。

> **2026-11-08 最终交互修订（优先于下文冲突处）**
>
> | 按键 | 最终行为 |
> |---|---|
> | 确认 | **开始 / 停止录音；进入多人模式不自动录** |
> | 左 | 触发 AI 回答；已打开时刷新 |
> | 右 | 关闭 AI 回答文字 |
> | 上 | 打开短语键盘：文字提问 / 文本指令 |
> | 下 | 打开当前 options（保留四布局指令） |
> | 返回 | 停止（若在录）→ 关回答 → 退出 |
>
> - 不做底部字幕；AI 回答过长时只显示 **关键词 + 短句**，不滚动长文；
> - 后端必须保存会议音频；本地分人；会中 AI 回答 + 会后总结；
> - 左右键不再“恢复系统定义”，以本表为准；
> - 五状态/四布局保留，确认人数改用文本指令 `确认人数`（因为确认键已用于录启停）。
>
> **落地记录（2026-11-08）**：确认启停/不自动录、左 AI/右关、上键键盘、
> 回答摘要（结论 + 关键词 + 短要点）、去掉底部字幕、音频留存、会后总结、
> 可编辑 system_prompt + 本地文字检索均已实现并通过测试。
> 未做：联网搜索（可选）、服务器部署（后续）。

## 1. 目标 / 非目标

### 目标

- 2 人以上会议：进入即录，自动分片（首片 15 秒、之后 55 秒），不需要一直按键。
- 说话人分离 + 逐段转写；跨切片不重复长人。
- 五状态：待命 / 处理中 / 待确认 / 完成 / 异常。
- 四布局：全部 / 只看待确认 / 按负责人 / 建议。
- 文本指令：确认人数、改人数、绑真实姓名、切布局、未知指令提示。
- **AI 回答**：左键或文字提问，基于会议转写 + 可编辑提示词 + DeepSeek；右键关闭。
- 返回键：停止采集、等队列、归档 meta.json。
- 本地优先：转写/分人本机跑；只有 AI 回答走 API；联网搜索可选。

### 非目标

- 不做逐字实时字幕/底部字幕（用户已确认取消）。
- 不做自动开始录音：确认键负责录启停（最终修订）。
- 左键 AI 回答、右键关闭回答文字（最终修订）。
- 不做声纹注册、真人姓名自动写人脉库。
- 不做强制第三方流式 ASR；火山/腾讯作为后续可选 provider。
- 不在这一阶段做服务器部署/容器化（后续单独排）。

## 2. 交互方案

### 2.1 入口

```text
待机 → 确认 → 模式选择（单人 / 多人）
     → 选「多人」→ 确认进入（未录制）
     → 确认开始录制 / 再确认停止录制
```

进入会议后不自动录；确认键负责启停。退出用返回键（若在录先停）。

### 2.2 按键（最终修订）

| 按键 | 会议内行为 |
|---|---|
| 确认 | **开始 / 停止录音**（不自动开始） |
| 左 | 触发 AI 回答；已打开时刷新 |
| 右 | 关闭 AI 回答文字 |
| 上 | 打开短语键盘：文字提问 / 文本指令 |
| 下 | 打开当前 options（四布局指令） |
| 返回 | 停止（若在录）→ 关回答 → 退出 |

> 回答过长时只显示结论 + 关键词 + 最多 3 条短要点，不滚动长文。
> 因为确认键已用于录启停，参会人数确认改用文本指令 `确认人数`。

### 2.3 五状态

| 状态 | 触发 | 镜片显示 |
|---|---|---|
| 待命 | 刚进会议、还没音频 | 会议待命 / 按一下开始听 |
| 处理中 | 有音频、还没分出发言人 | 会议中… 还没听到明确人声 |
| 待确认 | 检测到 ≥2 人且未确认 | 检测到 N 人 · 确认参会人 |
| 完成 | 已确认，或只有 1 人 | N 人 / 姓名 / 待办 / 段数 |
| 异常 | 图执行抛错 | 会议智能体出错 + 摘要 |

### 2.4 四布局

| 文本指令 | layout | 内容 |
|---|---|---|
| `只看待确认` / `待办` | `meeting_focus` | 待确认待办 |
| `按负责人` / `分组` | `meeting_compact` | 按负责人分组 |
| `给我建议` / `建议` | `meeting_advice` | 下一步建议 |
| `回到全部` / `全部` | `meeting` | 默认会议卡 |

AI 回答复用 `meeting_advice` 布局，不新增第五种布局：
rows 显示 3–5 条要点回答，options 提供 `回到全部 / 再问一个 / 保存`。

## 3. AI 回答（核心新增）

### 3.1 触发

1. **左键 AI 回答**（录音中/停录后均可）：用最近会议上下文 + 本地检索 + 当前提示词生成回答；
2. **文字提问**：上键短语键盘输入 `问 ...` / `查 ...`，或控制台/API 发 `text`；
3. **右键关闭**回答文字；确认键只负责录启停，不再触发回答。

### 3.2 链路

```text
左键 / 文字问题
  ↓
会议文字检索（本地，不联网）
  - 数据源：state.segments / meta.json 的 segments
  - 方法：关键词 + 字符 bigram 评分；取 top 6 + 最近 6 条
  - 可选：后续换 bge-m3 语义检索，不是必需
  ↓
提示词
  - 控制台「02 预设」里的 system_prompt（data/settings.json，可编辑）
  - + PRD/工作区固定会议回答提示词
  - + 检索到的会议原文
  - + 问题
  ↓
DeepSeek API（deepseek-chat）
  ↓
meeting_advice 布局：3–5 条要点 + 来源片段引用
```

### 3.3 无 Key 兜底

- 没配 `AR_LLM_KEY` 时，返回明确的「未配置大模型 Key，AI 回答暂不可用」，
  `degraded=true`，不再把用户问题复述一遍；
- 不假装模型可用；AI 回答是必要功能，必须配 DeepSeek Key 才能回答；
- 检查：`/api/agent/status` 的 `available` 必须是 `true`，否则看 `env.local.bat`
  或启动时是否加载了 `AR_LLM_KEY`。

### 3.4 分人稳定性（本次修复）

- 同一个人换语气/音量，CAM++ 质心相似度会从 0.9 掉到 0.7 左右；
  旧逻辑按 0.72/0.75 阈值会把它当成新发言人。
- 现在：
  - 跨切片匹配阈值 `AR_MEETING_SPEAKER_MATCH=0.78`；
  - 短于 `AR_MEETING_MIN_NEW_SPEAKER_SEC=4.0` 秒的簇**不新建发言人**，直接并入最像的已有人声；
  - 新增“短发言人合并”：<6 秒且相似度 ≥0.68 的发言人并回更长的人声；
  - 同切片聚类阈值 `AR_DIAR_MERGE_SIM=0.78`、最小段 1.0 秒、最小簇 1.5 秒。
- 实测：同一个人的 57 秒录音按 8 秒切片喂入，7 个切片全部只出 1 个发言人；
  3 人 demo 仍为 3 人，2 人 demo 仍为 2 人。
- ASR 错别字是本地 SenseVoice 的识别误差，和分人是两回事；配 Key 后可在
  会议纪要/回答里做一次语义校正，但实时原文不强行改写。

### 3.5 智谱 GLM 接入（本机实测）

`env.local.bat` 由 `start.bat` / `sim.bat` 加载（直接 `python src/server.py` 不会读）：

```bat
set "AR_LLM_BASE=https://open.bigmodel.cn/api/paas/v4"
set "AR_LLM_MODEL=glm-5.3-flash"
set "AR_MEETING_ANSWER_MODEL=glm-4-air"
set "AR_MEETING_ANSWER_MAX_TOKENS=500"
set "AR_MEETING_SUMMARY_MODEL=glm-4-plus"
set "AR_LLM_KEY=..."
```

- `glm-5.3-flash` 是推理模型，答案质量好但左键一次约 **34 秒**，不适合 AR 实时问答；
- `glm-4-air` 非推理，左键实测 **约 3 秒**，答案结构正确；
- `glm-4-plus` 非推理，会后总结约 1–3 秒；想用 5.3 写总结可把
  `AR_MEETING_SUMMARY_MODEL` 换成 `glm-5.3-flash`，但停录等待会变长；
- 检查：`/api/agent/status` 的 `available` 必须为 `true`。

### 3.6 联网搜索（可选，不是核心）

- 仅在问题明确涉及外部事实时触发（`搜 ...`、最新政策/价格/新闻/对比）；
- 会议内部问题（谁说了什么、待办、时间）**不联网**；
- 搜索 API 可选：博查（中文）/ Tavily（中英，域名过滤）；结果只取 3–5 条，
  权威域名加权（gov.cn / edu.cn / 官方文档 / 权威媒体），无权威来源就明说；
- 不做也不影响会议模式验收。

## 4. 后端方案

### 4.1 保留

- `src/meeting_agent.py`：ingest → commands → diarize → merge → asr → actions → summary → view；
- `src/meeting_store.py`：`data/meetings/agent_<session>/meta.json` 原子写；
- `src/diarize.py` + `models/diarization/` + `models/campplus_zh_16k.onnx`；
- `src/settings.py` 的 `system_prompt`（控制台可编辑）；
- `src/llm.py` 的 `transcribe` / `answer_meeting`（扩展参数）；
- 单人模块、`src/diar.py` 路径修复、`tools/start-sim.ps1` 一键模拟器。

### 4.2 新增 / 修改

- `meeting_agent.py`：
  - state 增加 `question / answer / answer_sources / system_prompt / preset`；
  - `node_commands` 识别 `问 ...` / `查 ...` / 问句 → 不当作未知指令；
  - 新增 `node_answer`（或并入 commands）：本地检索 + `llm.answer_meeting`；
  - view 增加 `answer` 字段，layout 用 `meeting_advice`，rows 放回答；
  - `run_feed` 接收 `preset`，把预设按钮的 prompt（提词/待办/以前）作为本次回答指令。
- `llm.py`：`answer_meeting(context, question="", system_prompt="")`；
- `server.py`：`/api/agent/feed` 的 `text` 直接复用；不需要新增 PRD 的 `/api/meeting/*`；
- `meeting_store.py`：meta 增加可选 `answers` 数组（审计用，不强制）。
- 检索：先用 Python 关键词/字符 bigram，不引入新模型；长会议再评估 bge-m3。

### 4.3 数据

```text
data/meetings/agent_<session>/meta.json
  meeting_id / session / status / duration
  speakers[] / segments[] / actions[] / summary
  answers[]（新增，可选：question / answer / sources / create_time）
```

- **音频必须留存**：`audio_storage/<session>.pcm`，与会话一一绑定；
- **总结**：停录时用 DeepSeek 生成 `summary / key_points / action_items`，
  写 `meta.json` + 数据库，控制台详情展示；
- SQLite（`data/meetings.db`）保留作为转写/问答/总结索引；如果只想最小实现，
  也可以只写 meta.json，但音频与总结不能省。

## 5. 眼镜端方案（最终修订）

- 模式选择 → 多人 → **进入未录制**；确认开始/停止；
- 15 秒首片 / 55 秒后续自动切；
- 会议卡 rows + 五状态/四布局；
- 确认=录启停；左右=AI 回答/关闭；上=短语键盘；下=options；返回=归档；
- 不做底部字幕、不做逐字流式；
- AI 回答小屏显示：结论 + 3 个关键词 + 最多 3 条短要点；过长截断，不滚动；
- 文字提问：
  - 上键短语键盘以 `问` / `查` 开头，或含问号，走后端 `/api/meeting/ask`；
  - 其它短文本走会议指令（`确认人数` / `只看待确认` / `按负责人` 等）；
  - 控制台/API 可用 `text` 发长问题。

## 7. 验收

### 7.1 工作区既有验收（docs 20 §6）

1. 会议模式入口；2. 首片 15 秒自动分人；3. 2 人确认；4. 3+ 人确认；
5. 改人数；6. 绑真实姓名；7. 四布局；8. 未知指令提示；9. 跨切片不重复长人；
10. 返回归档；11. 55 秒长片；12. 静音/分人失败不崩。

命令：

```powershell
python test/meeting_agent_test.py
python test/meeting_two_speaker_test.py
python test/meeting_commands_test.py
node test/meeting_glasses_sim.js     # 需按文档口径更新断言
```

### 7.2 AI 回答验收

- 录音中按左键：基于最近上下文 + 本地检索返回结论/关键词/要点，不打断录音；
- 右键：关闭回答文字；
- 文本 `问 ...`：从会议转写检索相关片段并回答；
- 控制台改 `system_prompt` 后，回答风格/结构变化；
- 无 Key：返回兜底要点并标注；
- 回答不编造会议里没有的事实；需要外部事实时可选联网搜索。

### 7.3 赛题要求

- 五状态可观察；
- 至少两次连续界面调整：内容变化（布局/待办）+ 重点/布局变化（focus/compact/advice）；
- 语音 + 文本都能完成同一任务；至少一次跨方式纠正；
- 失败/旧结果处理：异常状态、无 Key 兜底、未知指令提示。

## 9. 风险

- **确认键语义**：最终只负责录启停；参会人数确认改用文本指令 `确认人数`，测试要覆盖。
- **短语键盘输入长问题很痛苦**：眼镜上只适合短指令；长问题走控制台/API。
- **AI 回答延迟**：DeepSeek 1–3 秒；没有字幕，界面只需在回答时显示“在想…”。
- **本地分人限制**：抢话/重叠会并人；演示尽量轮流说。
- **测试基线**：现有 `meeting_glasses_sim.js` 是按 PRD 写的，必须改成 docs 19/20 的按键流程。
- **不要为了全绿改单人录音契约**：单人另有负责人。
