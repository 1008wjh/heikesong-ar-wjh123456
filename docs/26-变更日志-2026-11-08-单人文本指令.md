## 为什么先做这个

评分里「多模态协同 20 分」和「自动化 25 分」都要求：文本也能完成任务、能跨方式纠正、
内容修改/重点与布局确实变化、旧结果不能冒充最新。眼镜端不动，这些都可以在后端做，
而且全部走现有的 `POST /api/agent/feed`（`text` 字段），没有新增接口。

## 现在能干什么

一句话指令，服务端直接改卡片（不调模型，几十毫秒返回）：

| 说/打 | 效果 |
|---|---|
| `只保留待办` / `只看日期` / `筛选 报价单` | `layout=focus`，只留匹配的要点 |
| `优先日期` / `先看承诺` | 匹配的排最前，其余保留 |
| `换成Lena` / `不是他，是王姐` | 改当前人，返回那个人的档案卡 |
| `不是他` / `认错了` | `待确认`，问换成谁 |
| `显示全部` / `回到刚才` | 回到人物卡 |
| `取消` / `不要了` | `异常 · 已取消` |

要点：

- **纠正会粘住**：`换成X` 之后，眼镜端下一片还会带它自己记的旧 `person_id`，
  服务端用 per-session 覆盖把它压住，否则改完下一片又变回原来的人。
- **指令不写档案**：`node_commit` 对指令直接跳过。
- **语音也认**：解析发生在转写之后，所以对着眼镜说"只留待办"同样生效。
- **取消竞态**：模型返回后再查一次 cancel 标记，旧结果作废，避免"取消后还弹旧结果"。

## 附带改动

- `GET /api/latest` 多返回一个 `session` 字段（同一个接口，不是新接口）。
  控制台拿到当前会话 id 后，就能把文本指令补进眼镜正在用的那个 session，
  眼镜在听时会通过现有轮询把新卡刷出来 —— 这是"跨方式协同"的演示通道。
- `test/agent_command_test.py`：17 项，覆盖内容修改、重点变化、换人、纠正粘住、
  找不到人、否认、恢复、取消、普通文本不误触发、latest 带 session。
