## 现象

用户和队友（马子轩）的微信通话录音（49 秒，两人都在库里、都有声纹），
识别人返回 `created: true, 陌生人A`。

## 排查结果

把 m4a 转成 16k 单声道 wav 后直接量：

| 指标 | 结果 |
|---|---|
| 录音 | 49.11s，峰值 9125，不是静音 |
| 两个声纹之间 | sim(wjh, 马子轩) = 0.37，是两个人 |
| 马子轩说话段 vs 他的声纹 | **0.49 – 0.53** |
| wjh 说话段 vs 他的声纹 | **0.51 – 0.58** |
| 分轨 | 最大簇 26.1s 把两个人并在一起；`sim_owner=0.364`，没到阈值，所以主人没被剔除 |
| 阈值 | 识别人用的是 `voice.THRESHOLD=0.72`，所以 0.51 被判成"不认识" → 建陌生人 |

结论不是声纹库坏了，是**远场/手机录音和注册时的近场麦克风差太多**：
同一个人掉到 0.5 左右，0.72 的阈值在这个场景下必然误判成陌生人。

另外发现一个副作用：失败那次已经建了「陌生人A」，它的声纹就是这段录音最大簇的拷贝，
下次再测会以 1.0 自匹配——已删掉。

## 改法

- 新增「识别人」专用阈值（不影响注册/扫码）：
  `AR_IDENTIFY_THRESHOLD=0.45`、`AR_IDENTIFY_MARGIN=0.08`；
- 主人剔除也用这个阈值（这段录音里 wjh 那一簇 0.576 被剔除，队友那簇 0.346 保留）；
- 没匹配到才建陌生人，阈值判断统一走 `voice.match(..., threshold=...)`；
- 删除误建的「陌生人A」，清掉它的声纹拷贝。

## 注意

- 真人录音不进仓库（`test/voice/rec_*.wav` 已加进 .gitignore）。
- 0.45 是针对"手机/会议录音"的校准；如果以后还有更远的录音，可以再降到 0.42 左右，
  但要看 margin，避免两个声线接近的人串号。
- 想更稳的话，建议**用一段 10–15 秒的通话录音重新注册**这两个人的声纹（同设备同场景），
  相似度会回到 0.8+，就不用依赖低阈值了。
