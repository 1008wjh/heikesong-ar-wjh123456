## 0. 30 秒版

> MemoryLens 是一副记忆眼镜：声纹认出对面是谁，镜片显示上次聊到哪、你答应过什么，并给出三条能接上的话。  
> 它服务两类人：慢热、容易紧张的人，和希望掌握节奏的人。  
> 关系是有复利的资产，MemoryLens 让这份资产在见面时可用。

## 一、第 1 页：01 / 场景与价值（10 分）

### 标题区

**眉标**  
JUNCTION CHINA 2026 · 智能穿戴赛道 · 亮亮视野 LEION  
作品说明 / 关系记忆层

**主标题**  
**MemoryLens 记忆眼镜**

**副标题**  
把一次见面，变成可继续的关系。

**定义**  
它用声纹认出对面是谁，把上次聊到哪、你答应过什么、这次能接的三句话放到镜片；按返回，对话归档。

### 开场：信息不在手边，关系就会停在寒暄

商业场合的第一次见面，往往决定还有没有第二次。名片留下联系方式，MemoryLens 留下下一次开口的理由。

《孙子兵法》说，知己知彼，百战不殆。商业社交不是战争，但这句话点出一个事实：多数尴尬来自信息不在手边——不知道对方是谁、上次聊到哪、自己答应过什么。准备充分的人，更容易掌握对话的主动权。

MemoryLens 把这层信息放到镜片：声纹认出对面是谁，档案显示上次聊到哪、你答应过什么，三条提词给出这次能接的话。按返回，对话归档。

关系是有复利的资产。多数人的关系数据散落在通讯录、聊天记录和记忆里，见面时无法被调用。MemoryLens 把声纹身份、对话要点、承诺与偏好，整理成一份本人可控的关系记忆库。

### 两类购买理由

- **对慢热、在社交场合容易紧张的人**：少一点临场搜索，多一点开口的把握。
- **对希望掌握节奏、对关系有掌控感的人**：少一点被动接话，多一点主动推进。

前者是情感刚需，后者是职业刚需；共同点是，都不想把重要的关系交给临场发挥。

### 它怎么工作

眼镜只负责采集、显示、按键；认人、抽取、提词、入库在服务器完成。

选单人 / 多人 → 说话，15 秒首片 → 声纹认人 → 三条提词 → 返回入库。

### 为什么是眼镜

手机也能查，但低头、解锁、滑屏的三秒，对话已经断了。眼镜是少数能抬头看、双手不停的屏幕；声纹是少数不用正脸、不挑光线的身份入口。

平台没有开放摄像头，我们因此没有把人脸识别作为主链路。192 维声纹更贴近正在对话的场景，也避免把社交变成人脸识别。

**为什么现在（可选，排版时可删）**  
三个条件同时成熟：AR 眼镜具备可用的显示与麦克风；声纹模型能在本地 20–50ms 完成；大模型能把档案与当下对话拼成可说的话。

### 差异化

| 方案 | 解决的问题 | 没有解决的问题 |
|---|---|---|
| 会议转写 | 内容留存 | 下一次开口仍要靠人 |
| 名片与 CRM | 事后记录 | 对话中无法调用 |
| 通用 AI 助手 | 知识问答 | 不掌握这个人的档案 |
| **MemoryLens** | **对话中、按人、按档案给出下一句** | **多人抢话时，分人仍可能出错** |

### 关系数据的三层结构

- **身份层**：声纹，确认是谁。
- **记忆层**：对话要点、承诺、偏好，确认聊过什么。
- **关系层**：上次见面、待办、跟进，确认关系走到哪。

三层数据互相喂养：身份层让记忆归位，记忆层让关系可检索，关系层让下一次提词更具体。

三层数据存在本机，可查看、可修改、可删除；音频只在本机转写，模型只接收文本；对方同意是前提。数据随使用累积，下一次开口越有依据。这份随使用累积的记忆库，是产品的长期资产。下一步是在授权前提下接入日历、CRM、名片，让关系资产进入工作流。

### 三个数字

**15s** 首片认人 · **3 条** 可说的话 · **0.998s** 提词 P50

## 二、第 2 页：02–06 按评审维度分点

### 02 / ARUI 设计与交互 · 25 分

640×480 单色，一行 Text 约 110px。HUD 采用窄列：每行 ≤6 个汉字、最多 6 行、超长轮播；长内容不溢出，也不遮视线。

层级：状态/计时 → 姓名 → 身份关系 → 2–3 行记忆 → 按键提示。第一眼看到的是人，不是菜单。

低干扰：提词只占下半屏，20 秒自动收起，录音不中断；待命不显示任何人名；多人场景不混入单人档案。

**五种状态**

| 状态 | 用户看到 | 触发 |
|---|---|---|
| 待命 | 「按一下开始听」 | 空闲 |
| 处理中 | 「在想… + 计时」 | 按确认 / 请求中 |
| 待确认 | 「是他吗？ + 候选」 | 歧义 / 低置信 |
| 完成 | 「卡片 + 提词」 | 识别 / 建议成功 |
| 异常 | 「没声音 · 检查麦克风」 | 静音 / 模型 / 网络失败 |

**两次连续调整**

| 输入（同一 session） | 镜片变化 | 类型 |
|---|---|---|
| 「只看待办」 | 只剩日期 / 跟进 | 内容 |
| 「优先日期」 | 日期置顶，layout=focus | 重点 / 布局 |
| 「只保留日期」 | 3 行 → 1 行 | 精简 |
| 「显示全部」 | 还原 3 行 | 内容 |

两次都在同一个 session 内完成，ARUI 自动更新，不重进页面。

### 03 / 自动化与智能体执行 · 25 分

一张 LangGraph 图，7 个节点：ingest → route → identify → extract → recommend → render → commit。

- **首片只认人**：15 秒首片不跑提词，避免刚开口就给错建议。
- **提词带档案**：simple / complex 与本段转写一起进提示词，建议针对当前这个人。
- **确认与权限**：歧义先待确认；文本指令只改画面不写档案；多人模式不入库；旧请求过期不写。
- **失败可降级**：503 / 坏 JSON → 规则兜底并标「兜底」；静音 → 「没声音」，不让模型编字；慢请求 stale 作废。

自动化的难点在取舍：什么时候不打扰、什么信息不该上镜。

### 04 / 多模态协同 · 20 分

语音负责当下，文本负责精确修正。同一个任务，两条路，同一份 view。

- **切换保上下文**：语音认王姐 → 文本「换成 Lena」→ 人变 Lena → 再语音（旧 person_id）→ 仍 Lena。
- **独立纠正 / 歧义先问**：「换成王」→ 待确认，列出王姐/王兴/王石，人不变；「就是他」→ 才执行。
- **上下文**：纯文本续片沿用上一片 person_id；换人必须显式「换成 名字」，避免身份静默漂移。

### 05 / 实时性与可靠性 · 10 分

**P50 0.998s / P95 1.427s / 文本 22ms。**

10 次连续提词，本地 SenseVoice + DeepSeek，含 HTTP 往返；700ms 轮询，rev 变化才重绘；离线 outbox 8s 补传；单段最长 30 分钟。

### 06 / 交付与真实性 · 10 分

8 项验收、24 项检查全部通过；10 次连续延迟；提交包不含密钥。

| 验收项 | 预期 | 实际 | 证据 |
|---|---|---|---|
| ① 新需求 | 新输入 → 处理 → ARUI | 完成；王姐，3 行提词 | case1 |
| ② 内容修改 | 换对象 / 范围 / 条件 | 只看待办→日期/跟进；只保留日期→1 行 | case2 |
| ③ 重点与布局 | 突出 / 精简 / 重排 | 优先日期置顶，layout=focus；3→2 行 | case3 |
| ④ 跨方式 | 语音↔文本、纠正、上下文 | 王姐→Lena→语音仍 Lena→文本仍在 | case4 |
| ⑤ 歧义与确认 | 先澄清、未确认不执行 | 换成王→待确认（3 候选），人不变 | case5 |
| ⑥ 服务失败 | 准确反馈、注明注入 | 静音→异常；503/坏 JSON 13 项 | case6 |
| ⑦ 连续请求 | 旧结果不覆盖最新 | 慢请求 stale=true；cancel「已取消」 | case7 |
| ⑧ 显示边界 | 不溢出、可区分 | rows≤6、单行≤52 字；详情 5 行 | case8 |

**平台提供**：IrisView FusionUI、LEION 模拟器、DeepSeek API、开源模型 CAM++ 与 SenseVoice。  
**我们开发**：LangGraph 7 节点智能体、22 个 HTTP 接口、人脉库与两档记忆、五状态 HUD、离线补传、控制台、切片与阈值策略、8 项验收与 10 次延迟脚本。

**边界**：不做人脸；声纹指标为合成语音实测；会议待办关键词规则版；50 条人物为构造演示数据；AI 建议可能跑偏，控制台入库前需人工勾选。

**下一步**：找 10 个真实用户做一周试用，把「敢不敢开口」变成可测量指标；不把计划写成已实现。

### 第二场景 / 会议模式

同一套能力迁移到多人会议：15s/55s 自动切片、说话人分离、逐段转写、行动项、会后归档；控制台可复盘。

已知限制：抢话 / 重叠可能并人；待办为关键词规则版。会议模式是第二场景，不改变一对一社交的主线。

## 四、用词与语气规范

- 少用「不是……而是……」，全文不超过两次。
- 不用「真正的」「一句话」「在这个时代」「赋能」「闭环」「抓手」。
- 不承诺治愈、读心、情绪识别、100% 准确。
- 未实现的能力标「下一步」，不写成已实现。
- 数字给来源；没有数据就不加形容词。
- 句子短，动词具体，少用感叹号和问句。
