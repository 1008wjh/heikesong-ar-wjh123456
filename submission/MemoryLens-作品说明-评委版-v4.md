# MemoryLens 记忆眼镜

## 作品说明

JUNCTION CHINA 2026 · 智能穿戴赛道 · 亮亮视野 LEION  
ARUI / 自动化 / 多模态

**把一次见面，变成可继续的关系。**

---

## 一、作品概述

MemoryLens 是一副面向一对一社交的 AR 记忆眼镜。它用声纹识别对话对象，在镜片上显示对方经授权的档案、上次对话要点，以及本次可用的三条提词；对话结束后，内容归档到本人的人脉库。

作品由三部分组成：眼镜端 FusionUI 应用、Python 服务、浏览器控制台。眼镜端只负责采集、显示、按键；服务端负责认人、抽取、提词、入库；控制台负责人物录入、声纹注册与会议复盘。运行于赛事指定 IrisView 模拟器，后端 Python 3.12。

一次典型使用：戴上眼镜 → 确认 → 选「单人」→ 与对方交谈 → 15 秒后镜片显示对方档案 → 按确认获得三条提词 → 按返回归档。

它解决的是“接续”问题：见人多、记不住；掏手机查询会打断对话；名片和 CRM 只能事后录入；通用 AI 助手不了解眼前这个人。

## 二、场景价值与创新 · 10 分

商业场合的第一次见面，往往决定还有没有第二次。名片留下联系方式，MemoryLens 留下下一次开口的理由。

《孙子兵法》讲知己知彼，百战不殆。放回日常社交，这句话并不指向算计，而指向准备：知道对方是谁、上次聊到哪、自己答应过什么，对话会更从容。

关系会随时间产生复利。多数人的关系数据散落在通讯录、聊天记录和记忆里，见面时无法调用。MemoryLens 把声纹身份、对话要点、承诺与偏好，整理成一份本人可控的关系记忆库。

**两类用户**

- 慢热、在社交场合容易紧张的人：降低开口成本，不用在几秒内搜索名字、上次话题和承诺。
- 销售、创始人、展会与校友会常客：掌握对话节奏，主动提问、主动兑现、主动推进。

**为什么是眼镜**

手机也能查，但低头、解锁、滑屏的三秒，对话已经断了。眼镜是少数能抬头看、双手不停的屏幕；声纹是少数不用正脸、不挑光线的身份入口。平台没有开放摄像头，本作品以声纹作为主身份入口，不做人脸识别。

**与现有方案的区别**

| 方案 | 做法 | 局限 |
|---|---|---|
| 会议转写 | 记录内容 | 不解决下一次开口 |
| 名片与 CRM | 事后录入 | 对话中无法调用 |
| 通用 AI 助手 | 知识问答 | 不掌握这个人的档案 |
| **MemoryLens** | **对话中按人、按档案给出下一句** | **多人场景见第七节** |

**关系数据设计**

- **身份层**：声纹，确认是谁。
- **记忆层**：对话要点、承诺、偏好，确认聊过什么。
- **关系层**：上次见面、待办、跟进，确认关系走到哪。

三层数据存在本机，可查看、修改、删除；音频只在本机转写，模型只接收文本；对方同意是前提。未来在授权前提下接入日历、CRM、名片，让关系记录进入工作流。

## 三、ARUI 设计与交互 · 25 分

640×480 单色，单行 Text 约 110px。HUD 采用窄列：每行 ≤6 个汉字、最多 6 行、超长轮播；长内容不溢出，也不遮视线。

层级：状态/计时 → 姓名 → 身份关系 → 2–3 行记忆 → 按键提示。第一眼看到的是人，不是菜单。

低干扰：提词只占下半屏，20 秒自动收起，录音不中断；待命不显示任何人名；多人场景不混入单人档案。

**五种状态**

| 状态 | 用户看到 | 触发 |
|---|---|---|
| 待命 | 「按一下开始听」 | 空闲 |
| 处理中 | 「在想… + 计时」 | 按确认 / 请求中 |
| 待确认 | 「是他吗？ + 候选」 | 歧义 / 低置信 |
| 完成 | 「卡片 + 提词」 | 识别 / 建议成功 |
| 异常 | 「没声音 · 检查麦克风」 | 静音 / 模型 / 网络失败 |

**两次连续调整**

| 输入（同一 session） | 镜片变化 | 类型 |
|---|---|---|
| 「只看待办」 | 只剩日期 / 跟进 | 内容 |
| 「优先日期」 | 日期置顶，layout=focus | 重点 / 布局 |
| 「只保留日期」 | 3 行 → 1 行 | 精简 |
| 「显示全部」 | 还原 3 行 | 内容 |

两次都在同一个 session 内完成，ARUI 自动更新，不重进页面。

## 四、自动化与智能体执行 · 25 分

一张 LangGraph 图，7 个节点：ingest → route → identify → extract → recommend → render → commit。声纹用 CAM++，转写用本地 SenseVoice，提词用 DeepSeek；LangGraph 负责编排。

- **首片只认人**：15 秒首片不跑提词，避免刚开口就给错建议。
- **ARUI 自动更新**：render 把状态、布局、rows 组装成 view；commit 把要点写回档案。
- **提词带档案**：simple / complex 与本段转写一起进提示词，建议针对当前这个人。
- **确认与权限**：歧义先待确认；文本指令只改画面不写档案；多人模式不入库；旧请求过期不写。
- **失败可降级**：503 / 坏 JSON → 规则兜底并标「兜底」；静音 → 「没声音」，不让模型编字；慢请求 stale 作废。

自动化的难点在取舍：什么时候不打扰、什么信息不该上镜。

## 五、多模态协同 · 20 分

语音负责当下，文本负责精确修正。同一个任务，两条路，同一份 view。

- **切换保上下文**：语音认王姐 → 文本「换成 Lena」→ 人变 Lena → 再语音（旧 person_id）→ 仍 Lena。
- **独立纠正 / 歧义先问**：「换成王」→ 待确认，列出王姐/王兴/王石，人不变；「就是他」→ 才执行。
- **上下文**：纯文本续片沿用上一片 person_id；换人必须显式「换成 名字」，避免身份静默漂移。

## 六、实时性与可靠性 · 10 分

**P50 0.998s / P95 1.427s / 文本 22ms。**

10 次连续提词，本地 SenseVoice + DeepSeek，含 HTTP 往返；700ms 轮询，rev 变化才重绘；离线 outbox 8s 补传；单段最长 30 分钟。

---

## 七、会议模式（第二场景）

同一套能力迁移到多人会议：15s/55s 自动切片、说话人分离、逐段转写、行动项、会后归档；控制台可复盘。

限制：抢话 / 重叠可能并人；待办为关键词规则版。会议模式是第二场景，不改变一对一社交的主线。

**团队分工**

平台与开源提供：IrisView FusionUI、LEION 模拟器、DeepSeek API、CAM++ 与 SenseVoice 模型。  
我们开发：LangGraph 7 节点智能体、22 个 HTTP 接口、人脉库与两档记忆、五状态 HUD、离线补传、控制台、切片与阈值策略、8 项验收与 10 次延迟脚本。
