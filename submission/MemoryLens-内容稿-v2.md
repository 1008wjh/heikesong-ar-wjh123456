# MemoryLens · 作品说明内容稿 v2

> 这一版先定「说什么、什么先说」。样式下一轮再定。
>
> 主线：**社交记忆**。最大的创意不是「会议纪要」，是「知己知彼」的社交主动权；最锋利的入口不是「效率」，是「社恐也能开口」。

---

## 0. 30 秒版（先看这一段就够）

> MemoryLens 是一副「记住人」的眼镜。  
> 它不替你社交，只让社恐 / 慢热的人不再卡在开口前的三秒。  
> 它用声纹认出对面是谁，把上次聊到哪、你答应过什么、这次能接的三句话放到镜片。

## 一、第 1 页正文（先让人相信这件事值得做）

### 眉标

JUNCTION CHINA 2026 · 智能穿戴赛道 · 亮亮视野 LEION  
作品说明 / 社交记忆层

### 主标题

**MemoryLens 记忆眼镜**

### 副标题

见一个人，聊两句，镜片浮出：他是谁、上次聊到哪、这次该说什么。

### 题眼（大字）

**社交的胜负手，常常不在口才，而在检索。**

### 核心段

《孙子兵法》说，知己知彼，百战不殆。社交不是战争，但这句话点破了一个日常：很多尴尬，不是不会说话，而是不知道对面是谁、上次聊到哪、自己答应过什么。

MemoryLens 把这层信息放到镜片上：**知己**，是记得自己答应过什么；**知彼**，是知道对方是谁、上次聊到哪；**不殆**，是不失礼、不失约、不冷场。

它不是教你说话，是把下一句递到你嘴边。

### 但这不是情报战

「知彼」只知道对方愿意让你记住的部分：本人录入、对方同意、可删除；音频只在本机转写，模型只收文本。我们不爬取、不人脸、不显示未授权信息。

所谓主动权，不是拿捏对方，而是把对话的主动权拿回来：不用在寒暄里耗内存，能主动提问、主动兑现、主动结束尴尬。

### 为什么是眼镜

手机也能查，但「低头查手机」本身就有社交成本：解锁、滑屏、沉默的三秒，对话已经断了。

眼镜是少数「抬头就能看、双手不用停」的屏幕；声纹是少数「不用正脸、不挑光线、开口即识别」的身份入口。

平台没有摄像头，我们没有硬做人脸——192 维声纹反而更贴近「正在对话」的场景。

### 社恐：缺的不是话术，是一眼的检索

社恐最耗电的瞬间，不是开口，是开口前的三秒：他叫什么？上次聊到哪？我答应过他什么？大脑在检索，嘴就停了。

MemoryLens 把这三问从脑内搬到镜片：

- 15 秒自动认人，不用问「您是？」，不用偷看手机；
- 三条能接上的话，不是通用话术，是「对这个人的下一句」；
- 答应过的事先上镜，社交信用不靠记性。

它不治社恐，也不诊断；只降低启动成本——让「想聊」的人，不被「想不起来」挡住。

### 一个场景（剧本，非真实用户证言）

行业活动门口，小林（社恐，慢热）戴上眼镜。

15 秒，镜片浮出：王姐 / 产品经理 · 前同事 / 答应下周给报价单 / 猫叫豆豆。

她的第一句不是「你好我是……」，而是「豆豆最近还好吗？」

二十分钟后，她按返回，镜片显示「已记入 王姐 · 3 条」。

她没变成社交达人，只是没有再一次「想不起来」。

### 谁最需要

社恐 / 慢热的人：要的是「敢开口」。  
销售 / BD、创始人 / 投资人、展会与校友会常客：要的是「接得上」。  
同一层记忆，两种刚需。

名片和 CRM 都在事后；通用话术都在泛泛。MemoryLens 在对话中，按这个人给下一句。

### 三个数字

**15s** 自动认人 · **3 条** 可说的话 · **0.998s** 提词 P50

## 二、第 2 页正文（再让人相信它真的跑起来了）

### 它怎么工作

选单人 / 多人 → 说话，15s 首片 → 声纹认人 → 三条提词 → 返回入库。

眼镜只负责采集、显示、按键；认人、抽取、提词、入库都在服务器的一张 LangGraph 图里。

### ARUI：抬头看的界面

640×480 单色，一行 Text 约 110px。HUD 做成窄列：每行 ≤6 个汉字、最多 6 行、超长轮播；长内容不溢出，也不遮视线。

层级：状态/计时 → 姓名 → 身份关系 → 2–3 行记忆 → 按键提示。第一眼看到的是「人」，不是菜单。

低干扰：提词只占下半屏，20 秒自动收起，录音不中断；待命不显示任何人名；多人场景不混入单人档案，不擅自入库。

### 五种状态

| 状态 | 用户看到 | 触发 |
|---|---|---|
| 待命 | 「按一下开始听」 | 空闲 |
| 处理中 | 「在想… + 计时」 | 按确认 / 请求中 |
| 待确认 | 「是他吗？ + 候选」 | 歧义 / 低置信 |
| 完成 | 「卡片 + 提词」 | 识别 / 建议成功 |
| 异常 | 「没声音 · 检查麦克风」 | 静音 / 模型 / 网络失败 |

### 两次连续调整

| 输入（同一 session） | 镜片变化 | 类型 |
|---|---|---|
| 「只看待办」 | 只剩日期 / 跟进 | 内容 |
| 「优先日期」 | 日期置顶，layout=focus | 重点 / 布局 |
| 「只保留日期」 | 3 行 → 1 行 | 精简 |
| 「显示全部」 | 还原 3 行 | 内容 |

两次都在同一个 session 内完成，ARUI 自动更新，不重进页面。

### 多模态

语音负责「正在发生的对话」，文本负责「精确的修正」。同一个任务，两条路，同一份 view。

- **切换保上下文**：语音认王姐 → 文本「换成 Lena」→ 人变 Lena → 再语音（旧 person_id）→ 仍 Lena。
- **独立纠正 / 歧义先问**：「换成王」→ 待确认，列出王姐/王兴/王石，人不变；「就是他」→ 才执行。
- **上下文**：纯文本续片沿用上一片 person_id；换人必须显式「换成 名字」，避免身份静默漂移。

### 自动化

真正的自动化，不是「生成一段话」，是决定「此刻该不该打扰你」。

- 第一片 15 秒只认人，不跑提词；避免刚开口就给错建议。
- 提词带档案：simple / complex 与本段转写一起进提示词。
- 确认与权限：歧义先待确认；文本指令只改画面不写档案；多人模式不入库；旧请求过期不写。
- 失败可降级：503 / 坏 JSON → 规则兜底标「兜底」；静音 → 「没声音」，不让模型编字；慢请求 stale 作废。

### 实时与可靠

**P50 0.998s / P95 1.427s / 文本 22ms / 24/24。**

10 次连续提词，本地 SenseVoice + DeepSeek，含 HTTP 往返；700ms 轮询，rev 变化才重绘；离线 outbox 8s 补传；单段最长 30 分钟。

### 交付、证据与边界

**8 项验收 / 24 个检查，24 passed；10 次连续延迟；提交包不含密钥。**

| 验收项 | 预期 | 实际 | 证据 |
|---|---|---|---|
| ① 新需求 | 新输入 → 处理 → ARUI | 完成；王姐，3 行提词 | case1 |
| ② 内容修改 | 换对象 / 范围 / 条件 | 只看待办→日期/跟进；只保留日期→1 行 | case2 |
| ③ 重点与布局 | 突出 / 精简 / 重排 | 优先日期置顶，layout=focus；3→2 行 | case3 |
| ④ 跨方式 | 语音↔文本、纠正、上下文 | 王姐→Lena→语音仍 Lena→文本仍在 | case4 |
| ⑤ 歧义与确认 | 先澄清、未确认不执行 | 换成王→待确认（3 候选），人不变 | case5 |
| ⑥ 服务失败 | 准确反馈、注明注入 | 静音→异常；503/坏 JSON 13 项 | case6 |
| ⑦ 连续请求 | 旧结果不覆盖最新 | 慢请求 stale=true；cancel「已取消」 | case7 |
| ⑧ 显示边界 | 不溢出、可区分 | rows≤6、单行≤52 字；详情 5 行 | case8 |

**平台提供**：IrisView FusionUI、LEION 模拟器、DeepSeek API、开源模型 CAM++ 与 SenseVoice。  
**我们开发**：LangGraph 7 节点智能体、22 个 HTTP 接口、人脉库与两档记忆、五状态 HUD、离线补传、控制台、切片与阈值策略、8 项验收与 10 次延迟脚本。

边界：不做人脸；声纹指标为合成语音实测；会议待办关键词规则版；50 条人物为构造演示数据；AI 建议可能跑偏，控制台入库前需人工勾选。

下一步：找 10 个真实用户做一周试用，把「敢不敢开口」变成可测量指标；不把计划写成已实现。

## 三、这一版为什么这样写

### 1. 创意主线：从「会议纪要」换成「社交记忆」

大量 AR 眼镜作品在做「会议字幕 + 行动项」。这个方向正确，但拥挤，而且我们的说话人分离不是强项。

MemoryLens 的差异不在「记录」，在「关系」：  
**它不替你开会，它替你记住人。**

所以这一版把「一对一社交」放主线，「多人会议」只作为第二场景一句话带过。会议模式仍然在代码里、能跑，但不抢叙事。这是扬长避短的第一条。

### 2. 社恐是情感入口，不是全部用户

只讲效率，MemoryLens 会变成「销售工具」；只讲社恐，又会变成「小众辅助」。

这一版两个都讲，但主次清楚：

- **社恐 / 慢热**：情绪价值，愿意为「敢开口」买单；
- **销售 / 创始人 / 展会常客**：效率价值，愿意为「接得上」买单。

两边都不承诺「治愈」。我们只说「降低启动成本」，不说「提升社交能力」——因为没有用户研究，不能过度承诺。

### 3. 「知己知彼」怎么用才不油腻

这句话很容易被写成「社交情报战」。这一版刻意做了三次降温：

1. 把「百战」换成「不殆」：不是赢过谁，是不把重要的话掉在地上。
2. 把「知彼」限定为「被授权的记忆」：本人录入、对方同意、可删除。
3. 把「主动权」解释成「主动关心、主动兑现、主动结束尴尬」，不是拿捏。

伦理段紧跟创意段，不放到页脚小字。评委先看到边界，才会相信这个产品。

### 4. 扬长避短清单

| 策略 | 具体 |
|---|---|
| **放大** | 社交记忆 / 社恐破冰；声纹免手认人；无摄像头的隐私优势；三句提词；五状态；两次连续调整；失败与旧结果处理 |
| **收着** | 多人会议（第二场景，一句话）；人脸调试接口（不提，避免误会主链路）；50 条演示人物（只在边界里说明） |
| **不说** | 治社恐 / 提升社交能力（无用户研究）；读心 / 情绪识别；完美分人；零延迟 / 100% 准确；把未来计划写成已实现 |

### 5. 评审点覆盖

| 评审维度 | 分值 | 本稿对应内容 |
|---|---|---|
| ARUI 设计与交互 | 25 | 640×480 窄列、五状态、两次连续调整、20 秒收起、待命不显示人名 |
| 自动化与智能体执行 | 25 | LangGraph 7 节点、首片只认人、提词带档案、确认与权限、失败 / stale |
| 多模态协同 | 20 | 语音 + 文本同一任务、case4 跨方式、case5 歧义与纠正、person_id 上下文 |
| 实时性与可靠性 | 10 | P50 / P95 / 文本 22ms、10 次连续、700ms 轮询、outbox、30 分钟 |
| 场景价值与创新 | 10 | 社交记忆、社恐破冰、声纹免手、两档隐私记忆、提词不是总结 |
| 交付与真实性 | 10 | 8 项 / 24 检查、10 次延迟、平台 vs 团队、边界、无密钥 |

**赛题硬性要求对照：**

- 两次连续调整（内容 + 重点/布局）：第 2 页「两次连续调整」表 ✓

- 语音与文本都能完成同一任务：第 2 页「多模态」✓
- 一次输入方式切换 + 一次独立纠正 + 上下文：case4 / case5 ✓
- 实现边界：模型、接口、示例、工具、团队新增、人工辅助、固定流程、模拟数据：第 2 页「交付、证据与边界」+ 贡献拆分 ✓
- 8 项验收 + 10 次延迟 + 预期/实际/证据：第 2 页证据表 + 延迟数字 ✓
- 不超过 2 页、不含密钥：排版阶段控制 ✓

## 四、还需要你拍板的两件事

1. **社恐这条线，要讲到多深？**  
   现在是「情感入口 + 明确不治疗」。如果评委里有人对「社恐」敏感，可以再收一点，改成「慢热 / 社交场合容易紧张的人」。

2. **会议模式要不要保留？**  
   我建议保留一句话，作为「同一套能力，也能用于多人会议」的扩展，不展开。这样既不丢工作量，也不让主线跑偏。
